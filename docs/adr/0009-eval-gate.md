# ADR-0009: 평가 게이트 — 인프로세스 러너·장애 주입·녹화 응답

- 상태: 채택 (2026-10-20, Phase 7)
- 근거: PRD 5.6·7절, TRD 13절, 측정 데이터 `docs/adr/data/0009-eval-record.json`
- 도구: `scripts/run_eval.py`, `scripts/task.py eval-prepare|eval|eval-record|eval-replay`

## 결정

1. **러너는 운영과 같은 `chat.pipeline.run` 을 인프로세스로** 돈다. 파이프라인에 주입 지점은 실행기(`executor`)
   하나만 두었다 — 운영은 언제나 `execute_plan`. 계획·검증·조회 조건·실패 문구는 운영 코드 그대로다.
2. **장애 주입**(`evaluation.faults`): `executor_error`·`timeout` 은 실행기를 그 사유로 실패하는 것으로 바꾼다.
   `graph_down` 은 닿을 수 없는 Bolt 주소(`127.0.0.1:1`)의 **실제 드라이버**로 운영 실행기를 돌려 드라이버 오류 →
   `graph_unavailable` 분류까지 실제로 탄다. 그래서 `graph_down` 문항은 끝 객체가 실재하는 탐색 질문이어야 한다
   (끝 조건에 맞는 객체가 없으면 그래프 없이 0건이 맞는 답이다).
3. **권한**: `test_role` 이 골든셋의 `roles`(평가 전용 역할 → 타입 목록)에 있으면 그 권한으로, 아니면 DB 역할
   권한(`rbac.readable_types_for_role`)으로 돈다. 평가가 운영 권한 표에 역할을 만들지 않는다. 없으면 게시 버전
   전 타입을 읽는다(정답률 문항).
4. **판정·지표**(`evaluation.metrics`, 순수): TRD 13.2 계산식. 권한 위반 = 금지 값이 답·근거 제목에 나옴 OR
   읽을 수 없는 타입의 **객체** 근거(`o:Type/pk`)가 나옴. 집계 근거(`q:N`)는 타입이 없어 보지 않는다.
   실패 은폐 = 장애 문항이 `failed` 가 아님. 분모 0 이면 None.
5. **게이트**(`evaluation/gate.yaml`): 불변식(인용률 = 1, 은폐 0, 권한 위반 0, 답 없음 ①② 0, 장치 오류 0)은 확정,
   정답률 ≥ 0.9·추정 비율 ≤ 0.2·p95 ≤ 20초는 가안. 불변식은 값이 없으면 통과, 가안은 값이 없으면 실패.
6. **녹화 응답(카세트)**: CI 러너에 Ollama 가 없다. PR 마다 `domain-packs/sample/llm_cassette.json` 으로 파이프라인
   회귀를 돌린다(키 = 요청 본문 정규 JSON 해시). **카세트에 없는 요청은 실패**(지어내지 않는다)이고, 놓친 요청이
   하나라도 있으면 게이트 실패 — 프롬프트·데이터가 바뀌었는데 다시 녹화하지 않았다는 뜻이다. 녹화는 실제 모델로
   게이트를 통과한 실행에서만 한다(`eval-record`). 녹화 모드에서는 지연을 보지 않는다.
7. **평가 환경 분리**: 평가 DB(`ontobot_eval`)와 테스트 Neo4j 를 쓴다. `eval-prepare` 가 마이그레이션 → 샘플 팩
   시드(FK 링크 포함) → 그래프 재구축을 한다. 카세트 키에 데이터 블록이 들어가므로 녹화와 재생은 같은 시드여야 한다.
8. API 실행은 작업 큐(`eval_run`)로 워커가 돈다. 작업이 끝내 실패해 `running` 으로 남은 실행은 다음 실행 요청 때
   `failed` 로 닫는다(작업 없이 도는 CLI 실행은 건드리지 않는다).

## 측정(실제 모델, gemma4:e4b, 평가 DB)

| 지표 | 값 | 기준 |
| --- | --- | --- |
| 정답률(답할 수 있는 정상 문항 16) | 16/16 = 1.0 | ≥ 0.9(가안) |
| 근거 인용률 | 1.0 | = 1(불변식) |
| 추정 비율 | 0.019 | ≤ 0.2(가안) |
| 답 없음 문항 ①·② | 0/5 | 0(불변식) |
| 실패 은폐(장애 3) | 0 | 0(불변식) |
| 권한 위반(권한 3 + 전체) | 0 | 0(불변식) |
| p95 | 10.1초 | ≤ 20초(가안) |

카세트 재생: 놓친 요청 0, 판정 동일, 게이트 통과. 같은 실행을 개발 DB 에서 화면(작업 큐)으로도 돌려 통과했다.

측정 중 발견·수정:

1. **집계 근거를 객체 타입으로 읽어 전 문항을 권한 위반으로 셌다**(첫 실행 14건). 근거 키는 객체 `o:Type/pk`,
   집계 `q:N` 이다 → 객체 근거만 본다(단위 테스트 고정).
2. **작업이 실패하면 실행이 영영 `running`** — 오래된 워커(코드 갱신 전)가 `eval_run` 을 모르는 작업으로 세 번
   실패시켜 실측. 다음 실행 요청이 409 로 막혔다 → 고아 실행 닫기.
3. 남은 오답 1건(u01 "시설별 담당 점검원 이름은?"): 플래너가 `cannot_answer` 대신 "소유 조직 있음" 탐색을 짰고 답은
   ③(근거 없음)으로 닫혔다. 불변식(답 없음에 ①②)은 지켰다 — 안전하게 실패했지만 계획은 틀렸다. 정답률 분모에는
   들지 않는다(답할 수 없는 문항). 플래너 프롬프트를 바꿀 때 이 문항을 본다.

## 재검토 조건

모델·프롬프트·추출 스키마를 바꾸면 `eval-record` 로 실제 모델 게이트를 통과시키고 카세트를 함께 커밋한다.
PRD 7절 가안 수치가 정해지면 `gate.yaml` 의 `thresholds` 를 고친다. 실제 도메인 팩이 생기면 그 팩의 골든셋으로
같은 게이트를 건다.
