# ADR-0012: Action 실행과 메일·SMS 발송 — 승인 = 실행, 아웃박스 최소 한 번 발송

- 상태: 채택 (2026-10-20, Phase 10)
- 근거: PRD 5.3, TRD 17.1-2·3·4·5·6, 사용자 결정(부수효과는 앱 알림·메일·SMS)

## 맥락

Action 은 편집 레이어에 쓰고(write-back 없음) 알림을 보낸다. 메일·SMS 는 되돌릴 수 없다. 폐쇄망이라 발송은
사내 게이트웨이(SMTP 릴레이, SMS HTTP 또는 발송 테이블)뿐이고, 게이트웨이마다 접속 방식이 다르다.

## 결정

1. **정의는 온톨로지 문서에 둔다**(`action_type` 표, 버전에 묶여 게시). 게시 전 검사가 pk·제목·FK 변경,
   파라미터↔속성 자료형, 연락처 속성의 `pii_kind`, 자리표시자, 정정 문구를 막는다.
2. **상태는 `action_run` 한 행**: `previewed` → (승인) `executed` → (롤백) `rolled_back`, 그 밖에 `blocked`
   (미리보기에서 사전 조건·발송 조건 실패), `rejected`(거부·요청자 거둠), `failed`(실행 직전 재검증 실패).
   `request_id` 유일 인덱스가 같은 요청을 한 번만 받는다.
3. **승인 = 실행, 한 트랜잭션**. 게시 버전이 미리보기 때와 같은지, 대상·사전 조건이 여전히 맞는지 다시 보고
   편집을 쓰고 알림·발송 행을 넣는다. 재검증 실패는 예외로 되돌리지 않고 `failed` 기록으로 남긴다.
   승인 단계를 따로 두지 않은 것은 "승인했는데 실행이 안 된" 중간 상태를 없애기 위해서다.
4. **발송은 아웃박스(`notification_delivery`)를 커밋 뒤 워커가** 보낸다. 트랜잭션 안에서 보내면 롤백돼도
   문자가 나간다. 워커는 기한이 된 행을 `FOR UPDATE SKIP LOCKED` 로 집으며 시도 수를 올리고 임대 시각(5분)을
   민 뒤 커밋하고, 트랜잭션 밖에서 보낸다. 결과 기록 전에 죽으면 임대가 끝난 뒤 다시 보낸다 — **최소 한 번**
   발송이다(중복 가능성 < 유실). 재시도는 `retry_seconds × 시도 수`, 상한을 넘으면 `failed` 로 화면에 보인다.
   실행은 성공으로 남는다(편집은 이미 됐다).
5. **채널을 설정하지 않으면 꺼진다.** 그 채널을 쓰는 Action 은 미리보기에서 `blocked` — 보낸 척하지 않는다.
   개발용 `fake` 채널은 파일로 떨어뜨리고 미리보기에 경고를 낸다. `/readyz` 는 게이트웨이를 부르지 않는다.
6. **롤백**: 이 실행이 만든 활성 편집을 해제(이미 다른 편집으로 바뀐 것은 건드리지 않고 수를 보고),
   대기 중 발송은 취소, 나간(또는 실패한 — 게이트웨이까지 갔을 수 있다) 발송과 앱 알림 수신자에게 정정 문구를
   보낸다.
7. **문구는 템플릿 치환뿐**(`{이름}` 정규식 치환, `str.format` 금지 — 형식 지정·속성 접근이 끼어들지 않게).
   LLM 이 쓰지 않는다. 수신자 연락처는 원값으로 저장(보내야 하므로)하고 API·감사·로그에는 마스킹만 낸다.
8. 권한 판정(`can_request/decide/withdraw/rollback_action`)은 `security/rbac.py` 에만 둔다. 본인 승인은
   `allow_self` 일 때만, 롤백은 승인 역할 또는 관리자.

## 결과

- 발송 테이블 어댑터는 SQL 식별자(표·열)를 설정에서 받으므로 형식 정규식을 설정 검증과 조립 직전에 두 번 본다.
- 설치본은 `shared\notify.yaml`(릴리스 밖)을 쓴다 — 업그레이드로 게이트웨이 설정이 지워지지 않게.
- 실제 사내 게이트웨이 연동(인증 방식·응답 규약·발송 테이블 모양)은 운영 장비에서 확인해야 한다. 개발 PC 는
  가짜 채널과 HTTP 모의 전송으로만 검증했다.

## 재검토 조건

게이트웨이가 요청 ID 기반 중복 제거를 지원하면 `notification_delivery.id` 를 넘겨 "최소 한 번"을 사실상
"한 번"으로 만든다. 발송량이 커져 워커 하나로 밀리면 채널별 작업으로 나눈다.
