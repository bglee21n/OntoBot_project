# ADR-0008: 인터뷰 워크숍 — 면담자·추출기 구조와 모델

- 상태: 채택 (2026-10-20, Phase 6 측정)
- 근거: PRD 5.8, TRD 12절, 측정 데이터 `docs/adr/data/0008-workshop-*.json`
- 측정 도구: `scripts/spike_workshop.py` + 대본 `domain-packs/sample/interview.yaml`(8문항, 합성)

## 결정

1. **다음 질문은 상태기계가 고른다**(`workshop.topics`, 결정론적). 주제는 역할 → 업무 흐름 → 의사결정 →
   사용 데이터 → 예외 → **찾아보는 질문**(골든 질의 초안용으로 TRD 12절 다섯 주제에 하나를 더했다).
   주제가 채워졌다 = 면담자 평가가 `vague` 가 아님 AND 주제의 요구 요소(업무 흐름 → 객체 타입, 사용 데이터 →
   속성, 찾아보는 질문 → 골든 질의)가 세션에 있음. 되묻기는 주제당 2회, 넘으면 `incomplete` 로 넘어간다.
   질문 문장은 템플릿이 정본이고, LLM 은 모호한 답을 되묻는 문장만 쓴다.
2. **LLM 호출은 답 하나에 둘** — 추출기(`extractor`)와 면담자 평가(`interviewer`). 둘 다 구조화 출력.
   공급자 불가는 턴 전체 실패(503, 답도 저장하지 않음), 스키마 위반 2회는 그 단계만 빠지고 `warnings` 로 밝힌다.
3. **추출기 입력은 이번 답 하나**, 근거의 발언 id 는 서버가 붙인다. 후보마다 첫 필드가 `quote` 다
   (스키마 순서 생성 — 근거를 먼저 베끼게 한다, ADR-0004 의 키 순서 교훈).
4. **발언은 마스킹 저장, 이후 모든 단계가 마스킹 문장을 본다.** 근거 확인이 저장본과 같은 문장을 대조해야 한다.
5. **골든 질의는 "찾아보는 질문" 주제에서만, 면담자 질문을 베낀 후보는 버린다**(결정론적 거르기, 아래 측정 4).
6. 모델: 면담자·추출기 모두 **gemma4:e4b** 유지.

## 측정

| 모델 | 기대 충족 | 평가 일치 | 구조화 첫 시도 실패 | 근거 확인 통과 | 확정 검증 통과(이름 형식) | p50 턴 | 최대 턴 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| gemma4:e4b | 7/8 | 8/8 | 0 | 100% | 95.7% | 2.1초 | 4.4초 |
| gemma4:12b | 7/8 | 8/8 | 0 | 100% | 91.3% | 20.5초 | 46.5초 |

같은 품질에 지연이 10배라 e4b 를 둔다. 남은 1건(a05)은 값 없이 "위험등급을 봅니다"라고만 한 항목을
`string` 으로 본 것 — 답에 자료형 단서가 없으므로 검토 화면에서 고친다(확정 전에 사람이 본다).

측정 중 발견·수정:

1. **enum 값 목록 필드가 없었다.** "유형은 변전소, 전주, 배전함 중 하나"를 `enum` 으로 뽑고도 값을 담을 자리가
   없어 그 후보는 결코 확정 검증을 통과할 수 없었다 → 추출 스키마에 `enum_values`. 확정 검증 통과 83% → 96%.
2. **추출기 예시가 평가 도메인(시설·위험등급)이었다** — 베끼기와 이해를 가릴 수 없다(플래너는 처음부터 다른 도메인).
   민원 도메인 예시로 바꾸고 enum·링크·물음표 없는 질문을 모두 담았다.
3. **물음표 없는 "~도 자주 봐요"를 질문으로 뽑지 않았다** → 규칙 추가("질문 문장으로 바꿔 쓰되 quote 는 그대로").
4. **면담자의 질문을 골든 질의로 베꼈다**(브라우저 실측: "어떤 순서로 진행되나요? …", "무엇을 보고 판단하거나
   결정하시나요?"). quote 는 답에서 맞게 베껴 근거 확인을 통과했다 — 근거 확인으로는 못 잡는다. PRD 5.8 은
   에이전트 질문을 평가셋에 넣지 말라고 한다 → `extractor.keep`: 골든 질의는 `queries` 주제에서만, 면담자 질문과
   서로 포함 관계면 버린다.

## 결과

- 같은 객체를 답마다 다시 뽑는다(측정에서 `Facility` 가 7번) — 종류·이름 정확 일치면 새 요소를 만들지 않고 근거만
  덧붙여 검토 목록이 불어나지 않는다.
- 비슷한 이름(`type` 과 게시본의 `facility_type`)은 합치지 않는다(PRD 5.8 — 유사도 병합 금지). draft 에서 모델러가 정리한다.

## 재검토 조건

프롬프트·추출 스키마를 바꾸면 `scripts/spike_workshop.py --models gemma4:e4b` 로 다시 잰다. 실제 도메인
인터뷰 기록이 생기면 대본을 그것으로 늘린다(합성 8문항은 작다).
