# ADR-0015: 개발 콘솔 — 개발 PC 에서 소스·검사·평가·빌드·번들을 화면으로

- 상태: 채택 (2026-10-21, 사용자 결정)
- 근거: 사용자 결정(개발 PC 전용·PR·CI 까지·검사/평가/번들/개발 환경 모두), ADR-0013(Docker)·ADR-0014(배포 콘솔)

## 맥락

배포는 배포 콘솔(ADR-0014)로 화면이 생겼지만, 그 앞단 — 검사·테스트, 평가·카세트 녹화, 번들 만들기·서명, 개발 서버 —
은 `scripts/task.py`·`build_bundle.py`·`bundle_sign.py`·git 명령을 기억해서 쳐야 했다. 순서를 어기면 조용히 틀린다
(API 를 바꾸고 `openapi` 를 빼먹음, 프롬프트를 바꾸고 `eval-record` 를 안 해 CI 카세트 놓침, 커밋 전 `-dirty` 번들).

## 결정

| 항목 | 결정 |
| --- | --- |
| 위치 | **개발 PC 전용** 파이썬 프로세스 `devconsole/`(별도 uv 프로젝트, 컨테이너 아님, 운영 번들에 들어가지 않는다). `task.py devconsole` → http://127.0.0.1:8200 |
| 접근 | **127.0.0.1 만 바인드**(다른 주소면 시작 거부), 로그인 없음. `Host` 가 루프백이 아니면 거부(DNS 리바인딩), 상태 변경 요청은 `X-Ontobot-Dev: 1` 헤더 + 루프백 `Origin` |
| 명령 | **정본은 `scripts/task.py`** — 콘솔은 `TASKS` 를 읽어 작업 목록을 만들고 같은 명령을 부른다(명령을 두 곳에 적지 않는다). 그 밖은 고정 카탈로그(`build_bundle.py`·`bundle_sign.py`·git·gh). 셸을 거치지 않고, 화면은 임의 명령을 받지 않는다(브랜치·태그 이름은 정규식, 커밋 메시지는 인자) |
| 실행기 | 배포 콘솔과 **공유 패키지 `opsjobs/`**(작업 기록 `job.json`·`output.log`·`history.jsonl`, `==> ` 단계·마지막 JSON 결과, 색 코드 제거). 한 번에 한 작업. 기록은 `.devconsole/`(gitignore) |
| 서비스 | dev-api·worker·dev-web 는 작업과 달리 오래 사는 서비스 — 켜기/끄기/재시작·로그. 끌 때 프로세스 트리째(Windows 는 자손 목록을 미리 떠서 하나씩), 콘솔을 끄면 모두 끈다 |
| 소스 | 상태·diff·커밋(선택 파일, 공동 작성자 줄 선택)·브랜치 만들기/전환(커밋 안 한 변경이 있으면 전환 거부)·태그·푸시(`--set-upstream origin <브랜치>`). 충돌 해결·리베이스·강제 푸시는 하지 않는다(안내만). `main` 직접 커밋은 경고만 |
| GitHub | `gh` CLI(PR 목록·만들기, CI 실행). 토큰은 `gh` 가 관리 — 콘솔은 저장하지 않는다. 없으면 설치·로그인 안내 |
| 대시보드 | 검사별 마지막 결과와 그때의 커밋(지금과 다르거나 변경이 있으면 노란불). 기계적으로 판정할 수 있는 규칙만 경고: 커밋 안 한 변경(-dirty), API 를 바꿨는데 `openapi.json` 이 안 바뀜, 프롬프트·스키마 파일이 마지막 카세트 커밋 뒤 바뀜 |
| 번들 | 앱만/전체·zip·서명. 서명 키는 `.env` 의 `ONTOBOT_SIGNING_KEY` **경로만**(내용을 읽어 화면·로그에 내지 않는다, 공개키는 같은 이름 `.pub`). 검증·반출(복사 뒤 해시 재확인, 저장소 밖만)·릴리스 노트(번들 **옆** 파일 — 서명 밖) |

## 결과

- 화면은 `frontend/src/devconsole`(Vite 세 번째 입력 → `frontend/dist-devconsole`, 콘솔이 직접 서빙). 작업 기록·로그
  보기·신호등 부품은 `frontend/src/components/ops/` 로 옮겨 배포 콘솔과 함께 쓴다.
- 새 명령을 추가하면 `task.py` 에 넣는다 — 콘솔은 거기서 읽는다(설명·묶음은 `devconsole/.../catalog.py` 의 `TASK_INFO`).
- 배포 콘솔 이미지는 `opsjobs/` 를 함께 복사한다(`deploy/docker/deployer.Dockerfile`).

## 재검토 조건

여러 개발자가 한 빌드 서버를 함께 쓰게 될 때(그때는 로그인·권한이 필요하다 — localhost 전제가 깨진다).
