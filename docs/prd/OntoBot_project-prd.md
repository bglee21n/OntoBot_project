# PRD: 온톨로지 기반 챗봇 서비스 (가칭)

Palantir Foundry/AIP의 핵심 개념(Ontology, Action, Function, AIP Logic/Agent, 권한 모델)을 참조한 초안입니다. 팔란티어 기능 설명은 Palantir Foundry 공식 문서(2026-10-18 확인)와 대조해 검증했습니다. 단, ※ 표시 항목은 재확인이 필요합니다. 기능 제공 범위는 고객과 시점에 따라 다를 수 있습니다.

## 1. 배경과 문제 정의

- 일반 RAG 챗봇은 문서 조각을 검색해 답하기 때문에 엔티티 간 관계, 현재 상태, 실행 가능한 업무를 다루기 어렵습니다.
- 팔란티어의 접근은 데이터를 테이블이 아니라 비즈니스 객체(Object)와 관계(Link), 실행 가능한 행위(Action)로 모델링하고, LLM이 이 계층 위에서 동작하게 하는 것입니다.
- 목표: 조직의 데이터를 온톨로지로 구조화하고, 챗봇이 질의 → 추론 → 실행(승인 포함)까지 수행하는 서비스를 만든다.

## 2. 목표 / 비목표

### 목표

- 자연어 질의를 온톨로지 객체·관계 기반 질의로 변환해 근거 있는 답변 제공
- 챗봇이 정의된 Action을 통해 업무를 안전하게 실행(사람 승인 포함)
- 근거가 있는 답변마다 출처 객체와 계보(lineage) 추적 가능(5.0)
- 사용자 권한에 따라 보이는 객체·속성이 달라지는 보안 모델

### 비목표 (v1)

- 팔란티어 전체 플랫폼 복제(Pipeline Builder 등)
- 시뮬레이션·what-if 분석 — v1에서는 제외하고 v2에서 범위를 좁혀 제공한다(5.12)
- 범용 데이터 웨어하우스 기능
- 완전 자율 실행(항상 승인 단계 옵션 유지)

## 5. 핵심 기능 요구사항

**우선순위 정의**: P0 = MVP, P1 = v1, P2 = v1.5, P3 = v2. 한 절 안에 우선순위가 섞이면 항목마다 표시한다. 모든 항목은 8절 로드맵 표에 절 번호와 함께 다시 나온다.

### 5.0 응답 근거 정책 (P0, 값 계보는 P1)

모든 답변은 아래 세 등급 중 하나로 분류해 화면에 표시한다.

| 등급 | 조건 | 동작 |
|---|---|---|
| ① 근거 있음 | 사실 문장마다 대조를 통과한 인용이 있음 | 근거 카드·링크 첨부 |
| ② 일부 근거 | 대조를 통과한 인용이 하나 이상 있으나, 인용 없는 문장(해석·추론)이 섞임 | 인용 없는 문장에 "추정" 표시, 근거 있는 부분과 구분 |
| ③ 근거 없음 | 대조를 통과한 인용이 하나도 없음 | 답변을 지어내지 않고 거부한 뒤, 확인할 곳·다른 질문을 안내 |

**판정 방법 (규칙 기반)**

- 답변을 문장 단위로 나누고, 각 인용이 가리키는 객체·문서가 실제로 존재하는지, 그 문장이 말하는 값(수치·이름·상태)이 인용 대상에 그대로 있는지 대조한다. 판정은 정확 일치로 하고 유사도 점수는 쓰지 않는다.
- 집계 결과는 그 질의 결과(조회 조건 포함)를 인용 대상으로 삼는다.
- 대조에 실패한 인용(지어낸 인용)은 등급과 무관하게 답변에서 제거하고 트레이스에 남긴다.
- LLM이 스스로 매긴 등급은 쓰지 않는다.

**조회 실패는 실패라고 밝힌다.** 질의가 오류·권한 부족·타임아웃으로 실패했을 때 "해당 자료 없음" 같은 정상 답변으로 내보내지 않는다. 실패 사유는 답변과 트레이스(5.6)에 남긴다.

**값 계보 (P1)**: 근거 카드에서 그 값이 어느 원천 시스템·테이블에서 언제 동기화됐는지, 또는 편집 레이어(5.3)에서 누가 언제 바꿨는지 볼 수 있다. MVP에서는 마지막 동기화 시각만 표시한다(5.1).

### 5.1 온톨로지 관리

- (P0) Object Type / Property / Link Type 생성·수정 UI 및 YAML/JSON 임포트
- (P0) 단일 데이터 소스 매핑(컬럼 → 속성), 증분 동기화, 객체별 마지막 동기화 시각 표시
- (P0) 스키마 버전 관리
- (P1) 변경 영향 분석: 스키마뿐 아니라 Action·Function·에이전트 프롬프트·골든 질의셋·캐시까지 포함
- (P1) 비정형 문서 수집과 객체 연결(문서 ↔ 객체 링크). 5.2 하이브리드 검색의 전제다.
- (P2) 멀티 데이터 소스 연동(소스 사이에서 같은 객체를 식별하는 규칙 포함)
- (P2) 문서·DB 스키마에서 온톨로지 초안 자동 생성. 인터뷰 기반 초안은 5.8이 담당한다.

### 5.2 챗봇 질의

- (P0) 자연어 → 온톨로지 질의 계획(객체 검색, 링크 탐색, 집계) 변환
- (P0) 해석한 조회 조건(어떤 객체·필터·기간으로 조회했는지)을 답변에 함께 표시한다. 질의 계획이 틀렸을 때 사용자가 알아챌 수 있는 단서다.
- (P0) 답변 형식과 근거 표시는 5.0 정책을 따른다.
- (P0) 후속 질문에서 대화 맥락의 객체를 유지한다. 단, **맥락에는 객체 식별자만 저장하고 상태값(수치·상태·위치 등)은 매번 다시 조회한다.** 이전 턴의 값을 현재 값처럼 내보내지 않기 위함이다.
- (P1) 하이브리드 검색: 구조화 질의 + 벡터 검색(5.1의 문서 ↔ 객체 연결 이후)

### 5.3 Action 실행 (P1)

**정의**

- Action Type 정의 UI: 입력 파라미터, 사전 조건 검증, 변경 대상 객체·속성, 부수효과(알림 등), 승인 규칙
- MVP에서 5.8이 만든 Action 후보는 게시하지 않고 보관했다가, v1에서 이 UI로 정의한다.

**실행 흐름**

- 챗봇이 파라미터를 채워 미리보기 → 사용자 승인 → 실행
- **파라미터 검증**: LLM이 채운 값은 질문 원문과 온톨로지에 실재하는 값으로 대조한다. 대조되지 않는 식별자는 실행 전에 차단하고 사용자에게 확인을 요청한다.
- **멱등성**: 같은 요청이 재전송돼도 한 번만 반영되도록 요청 ID 기반으로 중복을 막는다.
- **승인 규칙**: Action마다 승인자 조건(요청자 본인 승인 허용 여부, 승인 권한 역할)을 정의한다.
- 모든 실행(미리보기·승인·거부·실패 포함)을 감사 로그에 남긴다.

**쓰기 대상: 편집 레이어**

- Action은 원천 데이터를 직접 바꾸지 않고 온톨로지의 편집 레이어에 쓴다. 사용자에게 보이는 객체 값은 원천 동기화 값 위에 편집 레이어를 덮은 값이다.
- **동기화와 충돌하면 편집 레이어가 우선한다.** 편집된 속성의 원천 값이 이후 동기화로 바뀌어도 편집 값을 유지한다.
- 단, 충돌을 조용히 넘기지 않는다. 충돌은 충돌 목록에 쌓고, 객체 카드에 "편집됨 · 원천 값 ○○ (동기화 시각)"을 함께 표시한다. 편집 값이 낡았는지 사람이 판단할 수 있어야 한다.
- 편집 해제: 권한자가 편집을 해제하면 원천 값으로 돌아간다. 해제도 감사 로그에 남긴다.
- 원천 시스템으로 되쓰기(write-back)를 할지는 10절에서 정한다.

**롤백과 보상**

- 편집 레이어 변경은 롤백한다.
- 외부 부수효과(알림 발송, 외부 시스템 호출)는 되돌릴 수 없으므로 Action 정의에 보상 절차(정정 알림 등)와 그 범위를 명시한다.

MVP에 미리보기만(실제 실행 없이) 넣을지는 10절에서 확정한다.

### 5.4 에이전트·도구 구성 (P2)

- 온톨로지 쿼리, Function, Action을 "도구"로 에이전트에 할당
- 에이전트별 시스템 프롬프트, 허용 도구, 가드레일 설정
- 멀티 에이전트 라우팅(도메인별 에이전트)

### 5.5 보안·거버넌스

- (P0) SSO, RBAC
- (P0) LLM에 전달되는 컨텍스트도 사용자 권한으로 사전 필터링
- (P0) **파생 저장소 권한 격리**: 의미 캐시·대화 요약·추천 등 파생 데이터는 권한 범위가 같은 사용자 사이에서만 재사용한다. 권한이 다른 사용자에게 캐시된 답변을 내보내지 않는다.
- (P0) **PII 마스킹**: 로그·트레이스에 남는 값과, 외부 LLM을 쓰는 경우 LLM에 보내는 컨텍스트 양쪽에 적용한다. 5.0의 근거 대조는 마스킹 전 원값으로 한다(가린 값으로는 대조가 성립하지 않는다).
- (P0) 프롬프트/응답 로깅, 데이터 보존 정책, 감사 로그 기록과 보존 기간 설정
- (배포 형태에 따라 결정) 온프레미스/프라이빗 모델 옵션. 온프레미스 배포면 P0이다(10절 2번).
- (P1) 객체·속성 단위 접근 제어
- (P1) 감사 로그 변조 방지(추가 전용 저장, 무결성 검증)

### 5.6 평가·관측성

- (P0) 골든 질의셋 기반 회귀 평가: 정확도, 근거 일치율, 응답 등급 분포(5.0), 권한 침투 테스트(RBAC 기준). 평가셋에는 근거가 없는 '답 없음' 문항을 포함한다.
- (P1) 권한 침투 테스트를 객체·속성 단위로 확대
- (P1) Action 파라미터 정확도 평가
- (P1) 트레이스 뷰: 질의 → 도구 호출 → 결과 → 등급 판정
- (P1) 사용자 피드백(좋아요/싫어요) 수집 및 개선 루프

### 5.7 자동화·알림 (P3)

- 온톨로지 상태 변화(예: 임계치 초과) 시 챗봇 선제 알림
- 알림에서 바로 Action 실행

### 5.8 현장 인터뷰 기반 공동 설계 (Live Design Workshop)

현업 담당자를 챗봇이 직접 인터뷰하고, 답변을 온톨로지·Action·챗봇 시나리오 초안으로 바꿔 확인·수정하는 설계 모드를 제공한다. 팔란티어가 현장 배치 엔지니어와 Ontology Manager를 오가며 모델을 다듬는 방식을 제품 안으로 가져온 기능이다.

#### 기본형 (P0, MVP)

- 인터뷰 에이전트(텍스트): 역할, 업무 흐름, 의사결정 지점, 사용 데이터, 예외 상황 순으로 질문하고, 답변에서 객체·속성·관계·Action 후보를 추출한다. 모호한 답은 되묻는다.
- 검토 화면: 인터뷰가 끝나면 추출한 요소를 목록(종류·이름·정의·근거 발언)으로 보여 주고, 현업 담당자가 요소별로 확정·수정·거절한다. 모델러가 최종 승인한 뒤 게시한다(초안 → 검토 → 게시).
- 산출물: 온톨로지 스키마 초안(JSON/YAML), Action 후보 목록(v1까지 보관, 5.3), 인터뷰 요약, 골든 질의셋 초안.
- 골든 질의셋: 인터뷰 중 수집한 현업의 실제 질문(예: "평소 무엇을 찾아보나요?"에 대한 답)과 기대 답변을 짝지어 만든다. 기대 답변은 현업 담당자가 확정한 것만 5.6 평가셋에 넣는다. 인터뷰 에이전트가 던진 질문 자체는 평가셋이 아니다.
- 보안: 인터뷰 발언은 권한 범위 안에서 저장하고, 개인정보는 마스킹하며, 보존 기간을 설정할 수 있다.

#### 확장형 (P1, v1)

- 분할 화면: 왼쪽은 대화(음성 입력, 모바일 지원), 오른쪽은 실시간 미리보기(온톨로지 그래프, Action 정의서, 데이터 매핑 상태).
- 샘플 데이터 질의 시연: 설계 중인 온톨로지에 샘플 데이터를 채워 "이 질문에는 챗봇이 이렇게 답한다"를 바로 보여 주고, 현업 담당자가 직접 질문을 입력해 검증한다. (실제 데이터 위에서 가정 값을 바꿔 보는 5.12 what-if와는 다른 기능이다.)
- 다중 인터뷰 병합: 여러 현업 담당자의 인터뷰를 합친다. 동의어·상충 정의는 **이름·값의 정확 일치에 근거한 후보로만 제안**하고, 병합 여부는 모델러가 결정한다. 유사도에 근거한 자동 병합은 하지 않는다.
- 성능 목표: 응답 후 미리보기 갱신 시간은 대상 모델·배포 환경에서 측정한 뒤 확정한다(가안 5초).

팔란티어 참조: [AI FDE](https://www.palantir.com/docs/foundry/ai-fde/overview/)(AI 기반 현장 배치 엔지니어)는 자연어 요청을 Foundry 작업으로 바꿔 객체·링크·Action 같은 온톨로지 요소를 만들고 수정한다. 본 기능은 이 방식을 차용하되 입력을 개발자 명령이 아니라 현업 담당자 인터뷰로 둔다. 차용하는 설계 원칙은 세 가지다.

- 변경을 바로 반영하지 않고 브랜치 제안으로 올려 검토 후 병합한다. 5.8의 초안 → 검토 → 게시 흐름이 여기에 대응한다.
- 사용한 도구와 프롬프트를 세션 기록으로 남긴다. 요소별 근거 발언 추적에 대응한다.
- 모든 작업은 사용자 권한 안에서 수행하고, 모델이 볼 컨텍스트는 사용자가 통제한다.

### 5.9 객체 탐색 (P1)

- 객체 검색과 상세 화면(속성, 링크, 연결 문서, 편집 이력, 값 계보)
- 관계 그래프 뷰(객체 인스턴스 단위)
- 챗봇 답변의 근거 카드에서 객체 상세로 이동
- 권한은 5.5를 그대로 적용한다.

### 5.10 Function (P1)

- 온톨로지 위 계산·집계·규칙 함수를 정의하고 버전 관리한다.
- 챗봇 도구로 노출한다(입력·출력 스키마 명시). Function 결과는 입력 조건과 함께 5.0의 인용 대상이 된다.
- 호출한 사용자의 권한으로 실행한다.
- 에이전트 도구로 할당하는 것은 5.4(P2)에서 한다.

### 5.11 외부 연동

- (P1) REST API: 질의, 객체 조회, Action 요청(승인 흐름은 5.3과 같다)
- (P2) 메신저 연동: 챗봇 질의와 Action 승인 요청 전달
- (P3) SDK 공개(OSDK 대응)

### 5.12 시뮬레이션 / what-if (P3)

- 가정 값을 실제 객체가 아니라 시나리오(편집 레이어의 격리된 사본)에 적용하고, Function 결과를 현재 값과 비교한다. 시나리오의 값은 실제 객체·동기화·Action에 반영되지 않는다.
- 답변에 "시나리오 결과"임을 표시하고 가정 값을 함께 보여 준다. 실제 값으로 오해하지 않게 하기 위함이다.
- 5.8 확장형의 '샘플 데이터 질의 시연'과는 다르다. 그쪽은 설계 검증용 샘플 데이터이고, 이쪽은 실제 데이터 위의 가정이다.
- 팔란티어 Vertex 전체 기능의 복제는 범위 밖이다.

## 6. 시스템 아키텍처 (개요)

1. 데이터 계층: 커넥터 → 정제/매핑 → 객체 저장소(그래프 또는 RDB+인덱스, 10절에서 확정) + 벡터 인덱스
2. 온톨로지 계층: 스키마 레지스트리, 링크 그래프, **편집 레이어(원천 값 위 오버레이, 충돌 목록, 시나리오 사본)**, Function/Action 런타임
3. AI 계층: 질의 플래너, 근거 대조기(5.0), 에이전트 오케스트레이터, LLM 게이트웨이(모델 교체 가능, 교체 시 5.6 회귀 평가 필수)
4. 보안 계층: 인증/인가, 정책 엔진, 감사 로그
5. 인터페이스 계층: 챗 UI, 관리 콘솔, 객체 탐색기, REST API/SDK, 메신저 연동

## 9. 리스크와 대응

- 온톨로지 구축 비용: 초기 도메인 1개로 좁히고, 인터뷰 워크숍과 템플릿 제공
- 환각/오실행: 인용은 원천과 대조해 지어낸 인용을 제거(5.0). 쓰기 작업은 승인 필수, 파라미터는 실재 값과 대조(5.3)
- 조용한 실패: 조회 실패가 "자료 없음"으로 둔갑하지 않도록 실패 사유를 답변과 트레이스에 남김
- 낡은 편집 값: 편집 레이어 우선 규칙 때문에 원천이 갱신돼도 옛 편집 값이 남을 수 있음 → 충돌 목록과 객체 카드의 원천 값 병기로 드러냄(5.3)
- 권한 누출: 검색 단계 필터링, 파생 저장소 권한 격리, 평가셋에 권한 침투 테스트 포함
- 데이터 품질: 매핑 검증, 데이터 신선도 표시, 상태값 매 턴 재조회
- 벤더/모델 종속: LLM 게이트웨이 추상화
- v1 범위 과다: P1 항목이 많으므로 v1 착수 시 Action(5.3)·Function(5.10)을 먼저, 나머지를 뒤로 나누는 재분할 검토
