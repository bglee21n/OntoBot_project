# 27장 문제 해결 사전

"이럴 때는 어떻게 하지?"를 증상별로 찾아보는 장입니다. 각 항목은 **증상 → 원인 → 할 일** 순서입니다.
해결되지 않으면 맨 끝 「27.9 관리자에게 알릴 때」를 보고 알려 주세요.

## 27.1 로그인·화면

| 증상 | 흔한 원인 | 할 일 |
| --- | --- | --- |
| "아이디 또는 비밀번호가 올바르지 않습니다" | Caps Lock, 한/영 전환, 아이디 앞뒤 빈칸, 비밀번호 오타 | 하나씩 확인하고 다시 입력. 계속되면 관리자에게 비밀번호 재설정 요청 |
| 비밀번호가 맞는데 로그인이 안 됨 | 계정 정지, 여러 번 틀려 잠시 막힘 | 몇 분 뒤 다시 시도. 안 되면 관리자에게 문의 |
| 쓰다가 갑자기 로그인 화면으로 돌아감 | 로그인 유지 시간(기본 8시간) 지남, 관리자가 역할을 바꿈 | 다시 로그인. 대화는 그대로 남아 있음 |
| 메뉴가 책과 다름 | 역할에 따라 메뉴가 다름 | 「3장」·「29장」에서 내 역할의 메뉴 확인 |
| 메뉴를 눌렀는데 "불러오는 중…"만 계속 보임 | 내 역할로 볼 수 없는 화면(예: 일반 사용자의 온톨로지) | 그 화면이 필요하면 관리자에게 역할 요청 |
| "이 화면을 볼 권한이 없습니다" | 내 역할로 쓸 수 없는 화면 | 위와 같음 |
| 화면 글자가 겹치거나 단추가 두 줄로 보임 | 창이 좁음 | 창을 넓히거나 브라우저 확대 비율을 100%로(Ctrl + 0) |
| 화면이 바뀌지 않음 | 브라우저가 옛 화면을 보여 줌 | **F5**(새로 고침). 그래도 안 되면 로그아웃 후 다시 로그인 |

## 27.2 질문했는데 답이 이상할 때

| 증상 | 원인 | 할 일 |
| --- | --- | --- |
| 숫자가 내가 아는 것과 다름 | ① 조회 조건이 내 뜻과 다름 ② 데이터가 최신이 아님 ③ 데이터가 정말 그 값 | 조회 조건부터 확인(「8장」). 맞으면 근거 칩 → 근거 카드의 **마지막 동기화** 시각 확인 |
| 조회 조건에 내 조건이 빠짐 | AI 가 조건을 놓침 | 조건을 더 분명히 다시 질문. 예: "경기 지역의 철탑 중에서 위험등급 4 이상" |
| 조회 조건의 값이 내 말과 다름(전주 → 철탑) | AI 가 질문을 잘못 이해함 | 그 답은 쓰지 말고 다시 질문. 반복되면 관리자·모델러에게 질문과 시각을 알림 |
| 등급이 ①인데 답이 틀림 | 등급은 "조회 결과와 맞다"는 뜻. 조회 조건이 틀리면 ①이어도 틀린 답 | 조회 조건 확인 |
| 문장 앞에 **추정** 이 붙음(②) | 그 문장의 값을 데이터에서 글자 그대로 찾지 못함 | 근거 카드로 직접 확인하고 쓰기 |
| 답 본문 없이 "근거 부족"(③) | 근거와 맞는 답을 만들지 못함 | 근거 칩을 직접 보거나 질문을 바꿈 |
| 답에 `**` 같은 기호가 보임 | AI 가 강조 표시를 섞어 씀 | 내용에는 문제없음. 무시해도 됨 |
| 목록이 20개에서 끊김 | 목록은 기본으로 최대 20건 | 조건을 좁히거나 "몇 개야?"로 개수를 먼저 물음 |
| 개수 답에 근거 칩이 "결과 1"뿐 | 개수·평균 같은 집계는 개별 근거가 아니라 계산 결과 | 조회 조건이 곧 근거. 대상 목록이 필요하면 "목록 보여줘"로 다시 |

## 27.3 실패·0건 안내가 나올 때

| 화면 문구 | 원인 | 할 일 |
| --- | --- | --- |
| 결과 0건 | 조건에 맞는 데이터가 없음 | 조건(이름·숫자)이 정확한지 확인. 없으면 정말 없는 것 |
| 조회 실패 · 질문 해석 실패 | 데이터에 없는 정보를 물었거나, 표현이 모호하거나, 볼 권한이 없는 종류를 물음 | 대상과 조건을 분명히. 등록된 정보인지 확인. 권한이 없을 수도 있음(27.6) |
| 조회 실패 · 권한 없음 | 내 역할로 볼 수 없는 데이터 | 필요하면 관리자에게 읽기 권한 요청 |
| 조회 실패 · 관계 저장소 연결 불가 | 관계 정보 저장소(Neo4j) 문제 | 잠시 뒤 다시. 관계가 없는 질문("○○ 위험등급")은 됨. 계속되면 관리자에게 |
| 조회 실패 · 시간 초과 / 실행 오류 | 일시적 시스템 문제 | 잠시 뒤 다시. 계속되면 관리자에게 |
| 조회 실패 · 결과 과다 | 조건에 맞는 대상이 너무 많음 | 조건을 좁힘 |
| 조회 실패 · 답변 모델 연결 불가 | AI 모델 서버 문제 | 잠시 뒤 다시. 계속되면 관리자에게 |
| 조회 실패 · 게시된 온톨로지 없음 | 설계도가 아직 게시되지 않음 | 모델러에게 문의 |
| "저는 등록된 데이터를 조회해 답합니다…" | 데이터 질문이 아니라고 판단 | 데이터에 대한 질문으로 다시 |
| "그 중 …"이 해석 실패 | 새 대화라 "그 중"이 가리킬 목록이 없음 | 처음부터 조건을 모두 적어 질문 |

## 27.4 데이터 변경 요청(Action)

| 증상 | 원인 | 할 일 |
| --- | --- | --- |
| "바꿔줘"라고 했는데 바뀌지 않음 | 정상. 채팅은 미리보기까지만 만듦 | Action → **내 요청** 에서 승인 상태 확인 |
| "요청을 그대로 만들 수 없습니다" | 대상이나 값이 질문에서 확실하지 않음 | **확인할 것** 을 읽고 양식에 대상(식별자)·값을 넣어 **미리보기** |
| "'…' 에 해당하는 … 객체가 없습니다" | 이름·식별자가 등록된 것과 글자가 다름 | 정확한 이름이나 식별자(예: `F-0004`) 입력 |
| "이름이 '…' 인 … 가 여러 개입니다", 또는 이름으로 요청했는데 질문 해석 실패 | 같은 이름의 대상이 둘 이상 | 식별자(예: F-0031)로 다시 요청(「22장 22.10」) |
| "'…' 값이 필요합니다" | 바꿀 값을 말하지 않음 | 양식에 값을 입력 |
| 상태가 **막힘**, "실행할 수 없습니다" | 사전 조건 ✗, 발송 채널 미설정, 수신자 상한 초과 | 이유를 읽고 요청을 거두거나 조건을 맞춘 뒤 새로 요청 |
| "사전 조건: 위험등급 gte 3" 처럼 영어가 섞임 | 화면이 조건 기호를 영어 약어로 보여 줌(gte 는 ≥, lte 는 ≤) | 뜻은 같음 |
| **승인하고 실행** 단추가 안 보임 | 내가 그 Action 의 승인 역할이 아님, 또는 내 요청 | 승인자에게 요청. 본인 요청은 원칙적으로 본인이 승인 못 함 |
| 승인했는데 **실패** 로 기록됨 | 승인하는 순간 다시 확인했더니 조건이 깨짐(그사이 값이 바뀜, 설계도가 바뀜) | 실패 사유를 읽고 요청자가 새로 요청 |
| 실행됐는데 원래 시스템 값이 그대로 | 정상. 편집 레이어에만 기록 | OntoBot 안에서는 바뀐 값이 **편집됨** 과 함께 보임 |
| 잘못 실행함 | — | 승인자나 관리자에게 **롤백** 요청. 메일·SMS 는 되돌릴 수 없어 정정 문구가 다시 나감 |
| 알림이 안 옴 | 받는 역할이 아님, 앱 알림만 설정됨, 연락처 미등록 | 관리자에게 알림 연락처 등록 요청 |

## 27.5 인터뷰 워크숍

| 증상 | 원인 | 할 일 |
| --- | --- | --- |
| 면담자가 같은 주제를 다시 물음 | 답이 모호하다고 판단 | 구체적인 이름과 예를 들어 다시 답 |
| "이번 답에서 요소를 뽑지 못했습니다" | AI 출력 오류 | 계속 진행. 필요한 후보는 검토 목록에서 확인 |
| "인터뷰 대상자만 답할 수 있습니다" | 다른 사람이 만든 인터뷰 | 인터뷰를 만든 사람이 답함 |
| 후보에 "발언에서 이 문장을 찾지 못했습니다" | 근거 문장이 내 말과 다름 | 고치거나 거절 |
| 확정했는데 "요소 내용이 올바르지 않습니다" | 후보 내용에 문제(예: 목록형인데 값 목록이 없음) | **수정** 으로 자료형 등을 고쳐 **수정 확정**(「15장」) |
| **검토 마치고 제출** 이 눌리지 않음 | 아직 검토 전인 후보가 있음 | 모든 후보를 확정·수정·거절 |

## 27.6 권한

| 증상 | 원인 | 할 일 |
| --- | --- | --- |
| 어떤 종류의 데이터만 물으면 "질문 해석 실패" | 그 객체 타입의 읽기 권한이 없으면 챗봇이 그 종류를 아예 모름 | 관리자에게 읽기 권한 요청(「21장」) |
| 새로 게시된 타입을 아무도 못 물음 | 새 타입은 읽기 권한이 자동으로 주어지지 않음 | 관리자가 **역할별 읽기 권한** 에서 부여 |
| 관리자인데 데이터를 못 봄 | 관리자 역할도 읽기 권한을 따로 받아야 함 | 관리 → 역할별 읽기 권한에서 admin 에 타입 부여 |

## 27.7 모델러

| 증상 | 원인 | 할 일 |
| --- | --- | --- |
| **게시** 단추가 흐림 | 게시 전 검사에 문제가 남음 | 검사 목록을 보고 고침 |
| "pk 속성 'id' 이 없습니다" | 객체 타입의 식별자 속성이 실제 속성 목록에 없음 | 속성을 추가하거나 타입을 지움 |
| "제목 속성은 Action 으로 바꿀 수 없습니다" | Action 이 pk·제목·FK 속성을 바꾸려 함 | 그 Action 의 바꿀 속성을 고침 |
| 접속 시험 "접속 정보가 없습니다" | 시크릿 참조가 가리키는 접속 정보가 서버에 없음 | 운영자에게 접속 정보 등록 요청 |
| 동기화 **실패**, "RowErrors" | 한 행이라도 값 변환 실패(예: 목록에 없는 시설 유형) | 오류의 행·열을 보고 원천 데이터나 매핑을 고친 뒤 다시 동기화 |
| 게시 직후 동기화가 "게시 버전에 객체 타입 … 이 없습니다"로 실패 | 워커가 게시 전에 읽은 설계도를 계속 씀(지금 판의 결함) | 운영자에게 워커 재시작 요청(「22장 22.9」) |
| 동기화 후 "읽음"이 원천 행 수와 다름 | 매핑한 표·조건이 다름 | 원천 표 확인 |
| 편집 충돌이 생김 | Action 으로 바꾼 뒤 원천 값도 바뀜 | 「19장」대로 확인 또는 편집 해제 |
| **지금 대사**·**재구축** 이 안 됨 | 관리자 전용 기능 | 관리자에게 요청 |

## 27.9 관리자에게 알릴 때

문제를 알릴 때 다음을 함께 적으면 관리자가 **트레이스**(처리 기록)로 빨리 원인을 찾을 수 있습니다.

1. 내 아이디
2. 문제가 생긴 시각(대략이라도)
3. 입력한 질문 그대로
4. 화면에 나온 조회 조건과 안내 문구(가능하면 화면 사진)
5. 기대한 답과 실제 답

> **알아 두기** 화면 사진은 Windows 의 **Win + Shift + S** 로 찍을 수 있습니다. 개인정보가 보이면 가린 뒤
> 보내세요.
