# 34장 한 장 요약 카드

역할마다 한 쪽씩, 자주 하는 일만 모았습니다. 이 장을 쪽 단위로 인쇄해 책상에 두고 쓰세요.

## 34.1 카드: 질문하는 사람

**질문 쓰기**

| 하려는 일 | 이렇게 묻기 |
| --- | --- |
| 개수 | `○○은 몇 개야?` |
| 목록 | `○○ 목록 보여줘`(최대 20건) |
| 상위 N | `○○이 가장 높은 □□ N개` |
| 묶어 세기 | `○○별 □□ 수` (대상을 분명히: "시설을 ○○별로") |
| 한 대상 | 식별자로: `F-0007 설비 용량은?` |
| 평균·합계 | `□□의 평균 ○○은?` |
| 관계 | `○○지사가 소유한 시설`, `○○에 있는 시설` |
| 날짜 범위 | `2015년 1월 1일부터 12월 31일까지` |
| 좁히기 | 같은 대화에서 `그 중 ○○만` |

**답 확인 세 단계**

1. **조회 조건** — 대상 · 조건(개수까지) · 한 일이 질문과 같은가?
2. **등급** — ① / ②(추정 문장 확인) / ③(다시 묻기)
3. **근거** — 중요한 숫자는 근거 칩 → 카드의 굵은 값

**기억할 것**

- ①이어도 조회 조건이 다르면 틀린 답.
- "결과 0건" = 없다 / "조회 실패" = 모른다.
- 이름·식별자는 글자 그대로(띄어쓰기·대소문자). 헷갈리면 식별자.
- 상대 날짜("10년 넘은")는 날짜로 바꿔 묻기.
- 같은 질문도 매번 같게 이해한다는 보장 없음 → 매번 조회 조건.

**막히면** 「27장 문제 해결 사전」 · 관리자에게: 아이디 · 시각 · 질문 · 화면 사진

## 34.2 카드: 변경 요청하는 사람

**요청**

- 채팅: `F-0004 위험등급을 3으로 바꿔줘. 사유는 ○○`
- 화면: Action → Action 요청 → Action · 대상 객체 pk · 값 → **미리보기**

**요청 카드에서 확인**

| 볼 곳 | 확인 |
| --- | --- |
| 대상 | 이름과 식별자가 맞나 |
| 바뀔 값 | 지금 → 실행 후 |
| 사전 조건 | ✗ 이면 막힘 |
| 알림 | 받는 사람 · 문구 · **되돌릴 수 없음** |

**그 뒤**

- 상태 확인: Action → **내 요청**
- 잘못 만들었으면(승인 전): **요청 거두기**
- 잘못 실행됐으면: 승인자에게 **롤백** 요청
- "확인할 것"이 나오면: 양식에 식별자·값 → **미리보기**

**기억할 것** 채팅은 미리보기까지만. 원래 시스템은 바뀌지 않음(편집 레이어). 메일·SMS 는 되돌릴 수 없음.

## 34.3 카드: 승인자

**매일**

1. Action → **승인 대기**
2. 요청 펼치기 → 바뀔 값 · 사전 조건 · 알림 · 요청자 · 사유 확인
3. **승인하고 실행**(메일·SMS 면 확인 창) 또는 거부 사유 → **거부**
4. 알림함 확인 → **모두 읽음**

**판단 기준**

- 업무 근거(점검 결과·보고서)가 있는가?
- 되돌릴 수 없는 알림(메일·SMS)의 받는 사람·문구가 맞는가?
- 거부할 때는 요청자가 무엇을 고칠지 알 수 있게 사유를 적었는가?

**잘못 실행됐을 때** 전체 기록 → 요청 펼치기 → **롤백** → 확인. 받은 사람에게 정정이 간다.

**실패가 나왔을 때** 승인 순간 재확인에서 조건이 깨짐 → 실패 사유를 요청자에게 알리고 새로 요청하게 한다.

## 34.4 카드: 현업 전문가(인터뷰)

**시작** 인터뷰 → 제목 → **새 인터뷰**(만든 사람이 답함)

**여섯 주제** 역할 → 업무 흐름 → 의사결정 지점 → 사용 데이터 → 예외 상황 → 찾아보는 질문

**답하는 요령**

- 구체적인 이름(변전소·전주), 숫자 기준(위험등급 4 이상), 판단 뒤 행동(점검 요청)
- 대상마다 보는 항목을 나열
- 마지막 주제: 실제로 묻듯이 + 기대 답
- 모르면 "모르겠습니다" / 개인정보는 말하지 않기

**검토**

| 단추 | 언제 |
| --- | --- |
| 확정 | 맞다 |
| 수정 → 수정 확정 | 이름·자료형 고침(enum 인데 값 없음 → int 등) |
| 거절 | 데이터에 없는 개념, 틀린 후보 |

질문 후보는 기대 답변 필요. 모두 처리 → **검토 마치고 제출**(제출 뒤 고칠 수 없음).

## 34.5 카드: 모델러

**설계도 고치기** 온톨로지 → 게시본의 **이 버전으로 새 draft** → 고치기 → **게시 전 검사** 통과 → **버전 비교** → **게시**

**게시 뒤 할 일**

1. 채팅으로 대표 질문 확인
2. 운영자에게 **워커 재시작**(지금 판)
3. 새 타입이면 관리자에게 **읽기 권한** 요청
4. 매핑·동기화
5. 평가

**규칙** api_name 은 바꾸지 않음 · 타입 api_name 대문자 시작, 속성 소문자 · pk·제목 속성 필수 · Action 은 pk·제목·FK 속성을 못 바꿈 · 메일·SMS Action 은 정정 문구 필요

**데이터 연결** 데이터 소스 추가(시크릿 참조) → **접속 시험** → 매핑 추가(원천 표 → 열 불러오기 → 짝짓기 → 모드 · 링크 · 일정) → **지금 동기화** → "읽음/바뀜/삭제" 확인

**동기화 실패** 한 행이라도 실패하면 전체 실패. RowErrors 의 행·열 → 원천 수정 또는 enum 값 추가

**편집 충돌** 데이터 소스 → 편집 충돌 → **확인**(편집 유지) / **편집 해제**(원천으로)

## 34.6 카드: 챗봇 빌더

**골든셋** 평가 → 새 골든셋 → 문항 추가(질문 · 기대 · failure · 필수 값 · 권한 · 장애 주입 · 답할 수 있음)

| 기대 | 언제 |
| --- | --- |
| ok | 정상 답(필수 값 넣기) |
| empty | 0건이어야 맞음 |
| failed | 실패해야 맞음(plan_invalid: 데이터에 없음 → 답할 수 있음 해제 / graph_unavailable: 장애 주입 graph_down) |
| not_query | 인사·잡담 |
| action_preview | Action 요청(화면 문항은 지어내기로 잡힘 — 파일로 넣기) |

**실행** 평가 실행 → 완료 → 보기 → 게이트 판정(불변식은 반드시 ✓) → 문항별 결과 ✗ 확인

**운영** 신고된 질문은 문항으로 · 게시 뒤·정기적으로 실행 · 게시 뒤에는 워커 재시작 후 실행

## 34.7 카드: 관리자

**사람** 관리 → 사용자 → 로컬 계정 추가 / 역할 체크 → **역할 저장** / **정지**(지우지 않음) / 알림 연락처 **고치기**

**권한** 관리 → 데이터 그룹 → 타입 체크 → **권한 저장**(새로 게시된 타입 잊지 말기, 관리자 역할도 필요)

**기록** 감사 로그 → 이벤트로 거르기(auth.login_failed · security.permission_changed · action.executed …)

**신고 처리** 사용자에게 시각·질문·화면 → 조회 조건 확인 → 운영자에게 트레이스 id → 트레이스(계획·attempts·지연·LLM 호출) → 모델러·빌더·운영자에게 전달

**그래프** 데이터 소스 → 그래프 투영 → 지금 대사 / 재구축(관리자 전용)
