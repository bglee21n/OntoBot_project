# 36장 낱말 풀이

가나다순입니다. 영어 낱말은 우리말 읽는 소리 순서에 넣었습니다.

| 낱말 | 뜻 | 처음 나오는 곳 |
| --- | --- | --- |
| 객체 | 실제 대상 한 건. 예: 수원 변전소 04호 | 1장 |
| 객체 타입 | 대상의 종류. 예: 시설, 조직, 지역 | 1장 |
| 거부 | 승인자가 요청을 실행하지 않기로 정하는 것. 사유를 적을 수 있다 | 12장 |
| 거두기(요청 거두기) | 요청자가 승인 전에 자기 요청을 취소하는 것 | 10장 |
| 게시 | 작성 중인 설계도(draft)를 확정해 챗봇이 쓰게 하는 것. 게시본은 하나뿐 | 16장 |
| 게시 전 검사 | 게시하기 전에 설계도에 문제(빠진 pk 등)가 없는지 프로그램이 확인하는 것 | 16장 |
| 게이트 | 평가 결과가 정해진 기준을 넘었는지 판정하는 관문. 통과/실패 | 20장 |
| 골든셋 | 정답을 아는 시험 질문 모음 | 20장 |
| 관계 | 링크와 같은 말 | 1장 |
| 근거 | 답이 기댄 데이터 | 5장 |
| 근거 대조 | 답의 숫자·이름이 조회 결과에 글자 그대로 있는지 프로그램이 확인하는 것 | 1장 |
| 근거 카드 | 근거 칩을 누르면 오른쪽에 열리는 상자. 그 대상의 지금 값과 출처 | 5장 |
| 근거 칩 | 답 아래의 작은 단추. 근거 데이터 하나를 가리킨다 | 5장 |
| 그래프 투영 | 객체 사이의 연결(링크)을 관계 전용 저장소(Neo4j)에 옮겨 두는 것. 관계 질문에 쓴다 | 19장 |
| 기대 답변 | 인터뷰에서 뽑힌 질문 후보에 적는, 그 질문의 올바른 답 | 15장 |
| 단계(진행 단계) | 답을 만드는 동안 보이는 진행 표시. 조건으로 바꾸는 중 → 조회 → 답 쓰기 → 근거 대조 | 4장 |
| 대사 | 원본 데이터와 그래프 투영이 서로 맞는지 맞춰 보는 것 | 19장 |
| 대화 | 질문과 답을 주고받은 묶음. 왼쪽 목록에 쌓인다 | 7장 |
| 데이터 소스 | OntoBot 이 데이터를 가져오는 회사의 원래 시스템(데이터베이스) | 18장 |
| 동기화 | 데이터 소스에서 데이터를 가져오는 일 | 1장 |
| 등급 ①②③ | 답이 근거로 확인된 정도. ① 근거 확인, ② 일부 추정, ③ 근거 부족 | 1장 |
| 링크(관계) | 객체 사이의 연결. 예: 시설 → 소유 조직 | 1장 |
| 롤백(되돌리기) | 실행한 Action 을 되돌리는 것. 바뀐 값이 원래대로 돌아가고 정정 알림이 간다 | 13장 |
| 마지막 동기화 | 그 값을 원래 시스템에서 마지막으로 가져온 시각 | 5장 |
| 막힘 | 사전 조건이 맞지 않거나 발송 설정이 없어 승인할 수 없는 요청의 상태 | 10장 |
| 매핑 | 원래 시스템 표의 어느 열이 OntoBot 의 어느 속성인지 짝지은 것 | 18장 |
| 모델러 | 데이터 설계도와 데이터 연결을 맡는 사람(역할 `modeler`) | 16장 |
| 미리보기 | Action 을 실행하기 전에 무엇이 바뀌는지 보여 주는 단계. 아무것도 바뀌지 않는다 | 9장 |
| 버전 | 설계도의 판. draft(작성 중) · 게시됨 · 보관됨 | 16장 |
| 보관됨 | 예전에 게시했던 설계도 버전. 고칠 수 없다 | 16장 |
| 사전 조건 | Action 을 실행해도 되는 대상의 상태. 예: 위험등급 ≥ 3 | 10장 |
| 속성 | 객체가 가진 정보 한 칸. 예: 위험등급 | 1장 |
| 승인 = 실행 | 승인 단추를 누르는 순간 실행된다는 뜻. 따로 실행 단추가 없다 | 12장 |
| 시크릿 참조 | 데이터 소스 접속 비밀번호를 화면에 적지 않고, 서버에 넣어 둔 이름만 적는 것. 예: `env:ONTOBOT_SRC_FAC` | 18장 |
| 식별자(pk) | 객체마다 하나뿐인 번호. 예: `F-0004` | 1장 |
| 알림함 | 앱 알림을 모아 보는 곳(Action 화면 아래) | 13장 |
| 온톨로지 | 회사 데이터의 설계도. 어떤 대상이 있고, 무엇을 가지며, 어떻게 이어지는지 | 1장 |
| 원천 값 | 원래 시스템에 있는 값. 편집됨 표시가 있으면 원천 값과 보이는 값이 다르다 | 13장 |
| 이어서 묻기 | 앞 답의 목록을 "그 중"으로 가리켜 묻는 것 | 7장 |
| 인터뷰 워크숍 | AI 면담자의 질문에 답하며 업무를 설명해 설계도 초안을 만드는 기능 | 14장 |
| 임포트·내보내기 | 설계도를 파일(YAML/JSON)로 넣거나 받는 것 | 16장 |
| 장애 주입 | 평가에서 일부러 장애를 흉내 내 실패를 숨기지 않는지 시험하는 것 | 20장 |
| 정정(알림) | 롤백했을 때 앞서 받은 알림이 무효라고 다시 보내는 알림 | 13장 |
| 제목 속성 | 객체를 사람이 알아보는 이름으로 쓰는 속성. 예: 시설명 | 16장 |
| 조회 계획 | AI 가 질문을 바꾼 "무엇을 어떤 조건으로 조회할지"의 계획 | 1장 |
| 조회 실패 | 질문을 이해하지 못했거나 시스템 문제로 조회하지 못함. "모른다"는 뜻 | 8장 |
| 조회 조건 | 챗봇이 질문을 이해한 내용. 프로그램이 실제 조회한 그대로 만든 문장 | 1장 |
| 추정 | 근거를 찾지 못한 문장 앞에 붙는 표시 | 5장 |
| 카디널리티 | 링크가 하나로 이어지는지(one) 여럿으로 이어지는지(many) | 16장 |
| 트레이스 | 질문 한 건의 처리 기록(계획·조회·AI 호출·시간). 관리자가 문제를 찾을 때 본다 | 21장 |
| 편집 레이어 | Action 으로 바꾼 값을 원래 데이터와 따로 두는 곳 | 1장 |
| 편집됨 | 근거 카드에서 그 값이 Action 으로 바뀐 값이라는 표시 | 13장 |
| 편집 충돌 | Action 으로 바꾼 뒤 원래 시스템 값도 바뀐 상태 | 19장 |
| 편집 해제 | 편집을 버리고 원래 시스템 값으로 돌아가게 하는 것 | 19장 |
| 평가 | 골든셋을 챗봇에게 실제로 물어 자동으로 채점하는 것 | 20장 |
| 후보(워크숍) | 인터뷰 답에서 뽑힌 객체·속성·관계·조치·질문의 초안. 사람이 확정해야 쓰인다 | 15장 |
| 감사 로그 | 로그인·권한 변경·데이터 변경 같은 중요한 일의 기록. 지울 수 없다 | 21장 |
| Action | 데이터를 바꾸는 미리 정해진 일. 미리보기 → 승인 = 실행 → 롤백 | 1장 |
| api_name | 설계도에서 쓰는 영문 이름. 한 번 정하면 바꾸지 않는다. 예: `risk_grade` | 16장 |
| draft | 작성 중인 설계도 버전. 고칠 수 있다 | 16장 |
| enum | 정해진 값 중 하나만 들어가는 자료형. 예: 시설 유형(변전소·철탑·전주) | 16장 |
| FK 속성 | 다른 객체의 식별자를 담은 속성. 링크를 만드는 데 쓴다. 예: 소유 조직 ID | 16장 |
| PII | 개인정보(이름·전화번호·메일 등). 표시하면 기록과 AI 전송에서 가려진다 | 16장 |
| SSO | 회사 통합 로그인 | 2장 |
