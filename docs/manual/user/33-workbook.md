# 33장 실습 워크북

교육 시간이나 혼자 익힐 때 순서대로 따라 하는 실습 열 개입니다. 실습마다 **목표 · 준비 · 단계 · 확인 · 정리 질문**
순서이며, 단계의 화면은 앞 장의 그림 번호로 안내합니다. 연습용 환경(예제 데이터)에서 하세요. 운영 환경에서 하면
실제 요청과 기록이 남습니다.

| 실습 | 주제 | 역할 | 시간 | 관련 장 |
| --- | --- | --- | --- | --- |
| 실습 1 | 로그인과 화면 익히기 | 누구나 | 10분 | 2·3장 |
| 실습 2 | 질문 다섯 개와 조회 조건 읽기 | 사용자 | 20분 | 4·5·6장 |
| 실습 3 | 근거 카드로 답 확인하기 | 사용자 | 15분 | 5장 |
| 실습 4 | "그 중"으로 좁혀 가기 | 사용자 | 15분 | 7장 |
| 실습 5 | 잘못 이해한 답 찾기 | 사용자 | 20분 | 8장 |
| 실습 6 | 변경 요청부터 롤백까지 | 사용자 + 승인자 | 30분 | 9~13장 |

## 실습 1 로그인과 화면 익히기

**목표** 로그인하고, 내 역할의 메뉴와 채팅 화면의 네 부분을 알아본다.

**단계**

1. 관리자에게 받은 주소로 접속해 로그인한다(「2장」).
2. 오른쪽 위에서 내 이름과 역할을 확인해 적는다: 이름 ________ 역할 ________
3. 맨 위 메뉴를 하나씩 눌러 보고, 내용이 보이는 메뉴와 비어 있는 메뉴를 적는다(「3장」).
4. 채팅 화면의 네 부분(대화 목록·제목·안내·입력 칸)을 찾는다.
5. 창을 좁혔다 넓혀 화면이 바뀌는 모습을 본다.
6. 로그아웃했다가 다시 로그인한다.

**확인** 「29장 역할별 권한표」의 내 역할 줄과 3번에서 적은 내용이 같은가?

**정리 질문** 공용 PC 에서 로그아웃하지 않으면 무슨 일이 생길 수 있는가?

## 실습 2 질문 다섯 개와 조회 조건 읽기

**목표** 질문 유형별로 묻고, 답보다 조회 조건을 먼저 읽는다.

**단계** 새 대화에서 아래를 차례로 묻고, 표의 빈칸을 채운다.

| 질문 | 조회 조건(그대로 옮겨 적기) | 대상·조건·한 일이 맞나 | 답 |
| --- | --- | --- | --- |
| 변전소는 몇 개야? | | | |
| 위험등급이 5인 시설 목록 알려줘 | | | |
| 시설 유형별 개수 알려줘 | | | |
| 변전소의 평균 설비 용량은? | | | |
| 서울에 있는 변전소는? | | | |

**확인** 다섯 개 모두 "맞음"인가? 하나라도 다르면 질문을 고쳐 다시 묻는다(「8장」).

**정리 질문** 조회 조건 끝의 "건수", "최대 20건", "○○별 건수", "○○ 평균"은 각각 무엇을 뜻하는가?

## 실습 3 근거 카드로 답 확인하기

**목표** 답의 숫자를 근거 카드로 직접 확인한다.

**단계**

1. `부산 철탑 02호의 위험등급과 설치일 알려줘` 를 묻는다.
2. 근거 칩을 눌러 근거 카드를 연다(그림: 5장 "인용된 칸이 굵게 보이는 근거 카드").
3. 답의 위험등급·설치일이 카드의 굵은 값과 같은지 본다.
4. 카드의 마지막 동기화와 값 출처를 적는다: ________________
5. `시설 유형별 개수 알려줘` 의 "결과 1" 칩을 눌러 계산 값과 안내를 본다.

**확인** 굵은 값과 답이 같은가? 집계 칩에 객체 카드 대신 계산 값이 나오는 이유를 설명할 수 있는가?

## 실습 4 "그 중"으로 좁혀 가기

**목표** 이어서 묻기로 조건을 좁히고, "직전 결과 N건 중"을 확인한다.

**단계**

1. 새 대화: `강남지사가 소유한 시설 목록 보여줘` — 몇 곳인가? ____
2. `그 중 위험등급이 4 이상인 것만` — 조회 조건의 N 은? ____ 결과는? ____
3. `그 시설들의 설치일 알려줘` — 조회 조건이 "시설 ID ∈ {…}"인가?
4. **새 대화** 를 누르고 `그 중 철탑만` 을 물어 실패를 본다.

**확인** 2번의 N 이 1번의 개수와 같은가?

## 실습 6 변경 요청부터 롤백까지(두 사람이 함께)

**목표** 요청 → 승인 → 확인 → 롤백의 한 바퀴를 직접 해 본다.

**단계**

| 순서 | 누가 | 할 일 | 확인 |
| --- | --- | --- | --- |
| 1 | 요청자 | 채팅: `F-0017 시설 위험등급을 3으로 바꿔줘. 사유는 실습` | 요청 카드: 4 → 3, 승인 대기 |
| 2 | 요청자 | Action → 내 요청 | 승인 대기 줄이 있음 |
| 3 | 승인자 | Action → 승인 대기 → 펼치기 → **승인하고 실행** | 실행됨 |
| 4 | 요청자 | 채팅: `F-0017 위험등급 알려줘` → 근거 카드 | 3, **편집됨** · 원천 값 4 |
| 5 | 요청자 | `위험등급이 4 이상인 시설은 몇 개야?` | 실행 전보다 하나 줄었나 |
| 6 | 승인자 | 전체 기록 → 그 요청 → **롤백** → 확인 | 롤백됨, 알림함에 정정 |
| 7 | 요청자 | `F-0017 위험등급 알려줘` | 다시 4, 편집됨 없음 |

**정리 질문** 실행해도 원래 시스템의 값이 바뀌지 않는 이유는? 메일·SMS 알림이었다면 롤백 때 무엇이 달라지는가?

## 실습 7 인터뷰 한 번 해 보기

**목표** 내 업무를 인터뷰로 설명하고, 후보를 검토해 제출한다.

**단계**

1. **인터뷰** → 제목(내 업무 이름) → **새 인터뷰**.
2. 여섯 주제에 답한다. 한 번은 일부러 짧게 답해 되묻는 것을 본다.
3. 마지막 주제에서 평소 묻는 질문 두 개를 기대 답과 함께 말한다.
4. 검토 목록에서 후보마다 확정·수정·거절한다. 데이터에 없는 개념은 거절한다.
5. 질문 후보에 기대 답변을 확인하고 **검토 마치고 제출**.

**확인** 후보마다 근거 발언이 내 말과 맞는가? 제출 뒤 "제출된 인터뷰입니다"가 보이는가?

## 실습 8 설계도에 속성 하나 더하고 게시하기

**목표** draft 를 만들고, 속성을 더하고, 검사·비교 후 게시한다.

**단계**

1. 온톨로지 → 게시된 버전의 **이 버전으로 새 draft** → 열기.
2. 시설 → **속성 추가**: api_name `inspection_team`, 표시 이름 `점검 담당 팀`, 자료형 string, 빈 값 허용.
3. 게시 전 검사가 통과인지 본다.
4. **버전 비교** 에서 "추가 property Facility.inspection_team"을 확인한다.
5. **게시** → 확인.
6. 운영자에게 워커 재시작을 요청한다(지금 판).
7. 채팅에서 `F-0001 점검 담당 팀 알려줘` 를 묻는다 — 데이터가 없으니 어떻게 나오는가?

**정리 질문** 새 속성에 데이터를 채우려면 무엇을 해야 하는가(「18장」)?

## 실습 9 골든셋 만들고 평가 돌리기

**목표** 문항 다섯 개로 골든셋을 만들고 평가 결과를 읽는다.

**단계**

1. 평가 → 새 골든셋 `실습 점검`.
2. 문항 추가(기대 · 필수 값):
   - `철탑은 몇 개 있어?` — ok · 10
   - `경남에 있는 시설 알려줘` — empty
   - `안녕하세요` — not_query
   - `다음 달 점검 일정 알려줘` — failed · plan_invalid · 답할 수 있음 해제
   - `강남지사가 소유한 시설 목록 보여줘` — failed · graph_unavailable · 장애 주입 graph_down
3. **평가 실행** → 완료 → **보기**.
4. 게이트 판정에서 불변식이 모두 ✓ 인지, 정답률이 몇 %인지 적는다.

**정리 질문** 4번째 문항에 "답할 수 있음"을 해제하는 이유는?

## 실습 10 신규 사용자와 권한

**목표** 계정을 만들고, 역할과 읽기 권한의 관계를 확인한다.

**단계**

1. 관리 → 로컬 계정 추가: `trainee01`, 표시 이름 `교육생`, 역할 user.
2. 그 계정으로 로그인해 `변전소는 몇 개야?` — 답이 나오는가?
3. 관리자로 돌아와 역할별 읽기 권한에서 `user` 의 시설 체크를 잠시 해제 → 권한 저장.
4. 교육생으로 같은 질문 — 무엇이 나오는가?
5. 다시 체크 → 권한 저장. 교육생 계정을 **정지**.
6. 감사 로그에서 `security.permission_changed` 로 거른다.

**정리 질문** 3번에서 다른 user 역할 사람들도 영향을 받는가? 왜 계정을 지우지 않고 정지하는가?

> **주의** 실습 10의 3번은 user 역할 **모든 사람**에게 영향을 줍니다. 반드시 연습용 환경에서 하세요.
