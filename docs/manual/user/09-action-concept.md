# 9장 Action 이해하기

3부(9~13장)는 데이터를 **바꾸는** 일을 다룹니다. 화면을 조작하기 전에 이 장에서 Action 의 규칙을 먼저 익히세요.
규칙을 알면 화면에서 무엇을 확인해야 하는지가 분명해집니다.

## 9.1 Action 이란

**Action** 은 데이터를 바꾸는, 미리 정해 둔 일입니다. 예제 데이터에는 세 가지 Action 이 있습니다(13장에서
하나를 더 만듭니다).

| Action | 대상 | 바꾸는 것 | 사전 조건 | 알림 | 승인 |
| --- | --- | --- | --- | --- | --- |
| 위험등급 조정 | 시설 | 위험등급 ← 새 위험등급(필수), 사유(선택) | 없음 | 앱 알림 → 관리자 | 관리자 |
| 점검 요청 | 시설 | 바꾸는 값 없음(요청과 알림만) | 위험등급 ≥ 3 | 앱 알림 → 관리자·현업 전문가 | 관리자 |
| 설비 용량 정정(17장에서 만듦) | 시설 | 설비 용량 ← 새 설비 용량(필수), 사유(선택) | 설비 용량 값 있음 | 앱 알림 → 관리자 | 관리자 |

정해 두지 않은 일은 할 수 없습니다. 예를 들어 "시설 이름 바꿔줘"는 그런 Action 이 없으므로 요청할 수
없습니다. 필요한 Action 은 모델러가 만듭니다(「17장」).

## 9.2 늘 같은 순서

모든 Action 은 같은 순서를 밟습니다.

| 단계 | 누가 | 화면 상태 | 데이터 |
| --- | --- | --- | --- |
| ① 요청(미리보기) | 요청자 | **승인 대기** 또는 **막힘** | 아직 그대로 |
| ② 승인 = 실행 | 승인자 | **실행됨** 또는 **실패** | 바뀜(편집 레이어) |
| ②' 거부 | 승인자 | **거부** | 그대로 |
| ②'' 거두기 | 요청자 | **거부**(사유: 요청자가 거뒀습니다) | 그대로 |
| ③ 롤백 | 승인자·관리자 | **롤백됨** | 원래대로 |

몇 가지 중요한 점이 있습니다.

- **미리보기만으로는 아무것도 바뀌지 않습니다.** 무엇이 어떻게 바뀌는지, 누구에게 알림이 가는지 보여 줄
  뿐입니다.
- **승인이 곧 실행입니다.** 승인자가 **승인하고 실행** 을 누르는 순간 실행됩니다. 따로 실행 단추가 없습니다.
- 승인하는 순간 서버가 **한 번 더 확인**합니다. 그사이 대상 값이 바뀌어 사전 조건이 깨졌거나 설계도가
  바뀌었으면 실행하지 않고 **실패**로 남깁니다.
- 요청자는 원칙적으로 자기 요청을 승인할 수 없습니다(Action 을 만들 때 "본인 실행 가능"으로 정한 경우만 예외).

## 9.3 채팅은 미리보기까지만

채팅 칸에 "F-0004 위험등급을 3으로 바꿔줘"라고 말하면, 챗봇은 **미리보기 요청만** 만들고 실행하지 않습니다.
실제 변경은 언제나 사람(승인자)이 정합니다.

또 챗봇은 확실하지 않은 대상이나 값을 **짐작해서 채우지 않습니다.**

- 질문에 대상의 이름이나 식별자가 글자 그대로 있어야 합니다(또는 바로 앞 답의 목록에 있어야 합니다).
- 바꿀 값도 질문에 있어야 합니다. "위험등급 바꿔줘"처럼 값이 없으면 값을 채우지 않고 물어봅니다.
- 이름이 같은 대상이 여럿이면 하나를 고르지 않고 후보를 보여 줍니다.

그래서 챗봇에게 바꿔 달라고 했는데 양식이 나오며 "확인할 것"이 보인다면, 챗봇이 일부러 짐작하지 않은
것입니다(「10장 10.4」).

## 9.4 실행하면 무엇이 바뀌나: 편집 레이어

실행해도 **회사의 원래 시스템 데이터는 바뀌지 않습니다.** OntoBot 안의 **편집 레이어**에 바뀐 값이 따로
기록됩니다.

- 채팅의 답과 근거 카드에는 바뀐 값이 보입니다. 근거 카드에는 **편집됨** 표시와 함께 원래 값(원천 값), 누가
  언제 바꿨는지가 보입니다.
- 개수·평균 같은 계산도 바뀐 값으로 합니다. 예를 들어 위험등급 1인 시설을 3으로 바꾸면 "위험등급 3 이상인
  시설 수"가 하나 늘어납니다(「13장」에서 실제로 18 → 19 가 됩니다).
- 원래 시스템에서 그 값이 나중에 바뀌어도, OntoBot 은 계속 편집 값을 보여 주고 **편집 충돌**로 알립니다. 모델러가
  편집 값을 유지할지 원래 값으로 돌릴지 정합니다(「19장」).

## 9.5 알림

Action 에는 알림이 붙을 수 있습니다. 알림은 세 가지 통로가 있습니다.

| 통로 | 받는 곳 | 되돌릴 수 있나 |
| --- | --- | --- |
| 앱 알림 | OntoBot 의 **Action** 화면 알림함 | 롤백하면 **정정** 알림이 따라감 |
| 메일 | 받는 사람의 메일함 | **되돌릴 수 없음** — 롤백하면 정정 메일이 감 |
| SMS | 받는 사람의 휴대전화 | **되돌릴 수 없음** — 롤백하면 정정 문자가 감 |

- 알림 문구는 Action 을 만들 때 정한 틀에 값만 끼워 넣습니다. AI 가 쓰지 않습니다.
- 메일·SMS 는 회사에서 발송 설정을 해야 쓸 수 있습니다. 설정이 없으면 메일·SMS 가 붙은 Action 의 요청은
  **막힘** 이 됩니다(보낸 척하지 않습니다).
- 알림은 실행이 확정된 **뒤에** 나갑니다. 실행이 실패하면 알림도 나가지 않습니다.

> **주의** 미리보기의 알림 칸에 **되돌릴 수 없음** 이 보이면 메일이나 SMS 가 나간다는 뜻입니다. 요청자도
> 승인자도 받는 사람과 문구를 꼭 확인하세요. 승인할 때 확인 창이 한 번 더 뜹니다.

## 9.6 Action 의 상태

| 상태 배지 | 뜻 | 다음에 할 수 있는 일 |
| --- | --- | --- |
| 승인 대기 | 요청됨. 승인자 결정 전 | 승인자: 승인하고 실행 / 거부 · 요청자: 요청 거두기 |
| 막힘 | 사전 조건 실패 등으로 승인할 수 없음 | 요청 거두기. 조건을 맞춘 뒤 새로 요청 |
| 거부 | 승인자가 거부했거나 요청자가 거둠 | 없음(필요하면 새로 요청) |
| 실행됨 | 실행 완료. 편집 레이어에 기록됨 | 승인자·관리자: 롤백 |
| 실패 | 승인 순간 재확인에서 조건이 깨져 실행하지 않음 | 없음(필요하면 새로 요청) |
| 롤백됨 | 실행을 되돌림 | 없음 |

## 9.7 Action 장 읽는 순서

| 장 | 내용 | 누가 |
| --- | --- | --- |
| 10장 | 채팅으로 요청하기 | 요청자(모두) |
| 11장 | Action 화면에서 요청하기, 기록 탭 | 요청자(모두) |
| 12장 | 승인·거부·롤백 | 승인자 |
| 13장 | 실행 뒤 답이 어떻게 바뀌나, 알림함 | 모두 |

## 9.8 이 장의 핵심

> **요령**
>
> - Action 은 미리 정해 둔 일만 할 수 있습니다.
> - 요청(미리보기) → 승인 = 실행 → (필요하면) 롤백. 미리보기만으로는 아무것도 바뀌지 않습니다.
> - 채팅은 미리보기까지만 만들고, 확실하지 않은 대상·값은 짐작하지 않습니다.
> - 실행해도 원래 시스템은 바뀌지 않고, OntoBot 안에서 **편집됨** 으로 보입니다.
> - 메일·SMS 는 되돌릴 수 없습니다.
