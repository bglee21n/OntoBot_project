# 36장 도입 현장 양식

새 부서나 새 업무에 OntoBot 을 들일 때 쓰는 양식입니다. 인터뷰 워크숍(14장) 앞뒤에서 할 일을 다섯 단계로 나누어 적었습니다.
목적과 성공 지표를 합의하고, 사람과 업무를 이해하고, 설계도로 옮기고, 파일럿 뒤 결과를 남기는 일입니다.

양식의 칸마다 그 값이 OntoBot 의 어디에 들어가는지 함께 적었습니다. 칸을 다 채우는 것보다 **다음 단계에 넘길 것**이
채워졌는지가 중요합니다.

- **누가 쓰나:** 도입 담당자(모델러·관리자)와 고객 쪽 책임자가 함께 씁니다. 현업 전문가에게는 2·3단계 양식의 질문만 보여 주면 됩니다.
- **참고:** 『팔란티어 FDE 현장 매뉴얼』 부록 1~16 의 구성을 참고해 OntoBot 의 기능과 절차에 맞게 새로 썼습니다.
- **앱에서 쓰기:** 메뉴 **도입**에서 도입을 하나 만들면 이 장의 양식 16종을 앱에 저장하고 인쇄할 수 있습니다. 도입은
  modeler·admin 이 만들고, 만든 사람이 owner 가 되어 구성원(owner 관리·editor 편집·viewer 읽기)을 아이디로 넣습니다.
  구성원이 아니면 관리자라도 그 도입이 보이지 않습니다. 도입 화면의 단계 탭은 단계마다 **다음 단계에 넘길 것**이
  채워졌는지 보여 줍니다. 두 사람이 같은 양식을 동시에 고치면 나중에 저장하는 쪽이 막힙니다 — **다시 불러오기**로
  최신 내용을 받은 뒤 고치세요. 양식 내용은 AI 에 보내지 않습니다.
- **양식 → 제품 보내기:** 도입 화면의 **양식 → 제품 보내기**에서 용어집(36.11)을 설계도 draft 로, 질문 후보(36.7·36.9·36.10)를
  도입 전용 골든셋으로, 성공 지표 목표(36.14)를 관리 화면의 목표로, 이해관계자(36.6)를 계정·그룹으로 옮깁니다. **미리보기**로
  바뀔 것을 먼저 보고 **적용**을 눌러야 반영됩니다. 이름이 글자 그대로 같은 것만 맞추고, 지우기·자료형 바꾸기·역할 빼기는
  하지 않습니다(설계도·관리 화면에서 직접). 설계도는 modeler, 골든셋은 bot_builder·modeler, 목표·계정은 admin 이 보냅니다.
- **파일럿 판단과 자산화:** 도입 화면의 **5 파일럿과 자산화** 탭에 판단 패널이 있습니다. 마지막 실제 모델 평가(재생 제외)의
  게이트·불변식, 성공 지표 목표와 지금 값, 36.14 에 적은 업무 지표를 한곳에 보이고, owner 가 판단과 사유를 남깁니다.
  불변식 위반이 있거나 게이트를 통과하지 못했으면 **보류**만 고를 수 있습니다. **zip 받기**는 게시 설계도·확정한 골든 문항·
  양식을 도메인 팩 모양으로 묶습니다. 객체 데이터는 담지 않고, 이름·아이디 같은 사람 정보 칸은 비웁니다.

## 36.6 이해관계자 지도

사람마다 OntoBot 에서 어떤 역할과 데이터 그룹을 가질지 정합니다. 이 표가 그대로 계정·그룹 설계의 초안이 됩니다
(21장, 29장). 앱에서는 관리자가 이 표를 **계정·그룹으로 보내기**로 옮깁니다. 아이디·그룹 이름이 **글자 그대로 같은**
계정·그룹은 이미 있는 것으로 보고, 없는 것만 만듭니다. 데이터 그룹 칸에는 그룹 이름(영문 소문자, 예: `inspection_team`)
이나 이미 있는 그룹의 표시 이름을 적고, OntoBot 역할 칸에는 `user`·`modeler` 같은 역할 이름을 쉼표로 적습니다.

| 분류 | 하는 일 | 대개 맡는 OntoBot 역할 |
| --- | --- | --- |
| 결정권자 | 예산·우선순위·승인 | 승인자, 필요하면 admin |
| 현업 사용자 | 일상 업무, 질문하는 사람 | user |
| 현업 전문가 | 업무 규칙을 아는 사람 | domain_expert(인터뷰) |
| 데이터·IT 담당 | 원천 DB 관리 | 원천 계정 제공, modeler 협업 |
| 설계 담당 | 설계도·Action 정의 | modeler |
| 품질 담당 | 골든셋·평가 | bot_builder |
| 운영자 | 설치·백업·업그레이드 | admin(운영자 매뉴얼) |

영향력·관심도는 상/중/하로 적습니다.

| 이름·직책 | OntoBot 아이디 | 관심사·걱정 | 영향력 | 관심도 | OntoBot 역할 | 데이터 그룹 | 읽기 / 고치기 타입 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| | | | | | | | |
| | | | | | | | |
| | | | | | | | |

영향력과 관심도에 따라 대하는 방법이 다릅니다.

- **둘 다 높음:** 함께 결정합니다(주간 회의).
- **영향력만 높음:** 결과를 정기적으로 알립니다.
