# 28장 증상별 해결표

사용자가 알려 오는 말, 또는 운영자가 본 화면으로 원인과 해결을 찾는 표입니다. 표의 "자세히"에 적힌 장에 실제 화면과
절차가 있습니다.

## 28.1 접속·로그인

| 증상 | 가능한 원인 | 확인 | 해결 | 자세히 |
| --- | --- | --- | --- | --- |
| 브라우저에 "이 페이지에 연결할 수 없습니다" | api 멈춤 | 현황: 응답 없음, api `Exited` | `docker compose start api` | 27.4 |
| 〃 (서버 안에서는 됨) | 방화벽, 포트 전달 | `netsh interface portproxy show v4tov4` | 예약 작업 `OntoBot-Host` 실행, 방화벽 | 27.8 |
| 재부팅 뒤 접속 안 됨 | 부팅 예약 작업 실패 | 작업 스케줄러의 마지막 실행 결과 | `OntoBot-Host` 수동 실행 | 27.8 |
| "아이디 또는 비밀번호가 올바르지 않습니다" | 비밀번호 틀림, 계정 정지, 없는 아이디 | 감사 로그 `auth.login_failed`, 사용자 목록의 상태 | 비밀번호 확인, **다시 사용**, 새 계정 | 6.1, 7.7 |

| 로그인 단추가 "확인 중…"에서 멈춤 | 데이터베이스 멈춤 | 현황: 사용 불가, postgres `Exited` | `docker compose start postgres` | 27.5 |
| 일하다 갑자기 로그인 화면으로 | 세션 만료(8시간), 역할 변경·정지 | 감사 로그 `security.role_changed` 등 | 다시 로그인 | 7.6 |
| 관리 메뉴가 안 보임 | admin 역할 없음 | 오른쪽 위 역할 표시 | 역할 부여(다른 관리자가) | 7.6 |
| 관리자 모두 잠김 | 관리자 정지·역할 제거 | — | 명령으로 새 관리자 | 7.9 |
| SSO 단추가 없음 | OIDC 설정이 비어 있음 | `app.env` 의 `ONTOBOT_OIDC_ISSUER` | 설정 후 반영 | 30장 |

## 28.2 질문과 답

| 증상 | 가능한 원인 | 확인 | 해결 | 자세히 |
| --- | --- | --- | --- | --- |
| 모든 질문이 "답변 모델 연결 불가" | ollama 멈춤 | 현황: 사용 불가, ollama `Exited` | `docker compose start ollama` | 27.1 |
| 관계 질문만 "관계 저장소 연결 불가" | Neo4j 멈춤 | 현황: 일부 저하 | `docker compose start neo4j` → 지금 대사 | 13.3 |
| 무엇을 물어도 "질문 해석 실패" | 그 사람이 읽기 권한 있는 데이터 그룹에 없음 | 사용자 탭의 데이터 그룹 칸, 데이터 그룹 탭 | 그룹에 넣기·권한 부여 | 8.2 |
| 어떤 사람만 갑자기 아무것도 안 나옴(0건) | 그룹의 읽기 행 정책이 깨짐(닫힌 쪽으로 동작) | 데이터 그룹의 **제한 있음** | 정책 고치기 | 8.6 |
| 특정 질문만 "질문 해석 실패" | 온톨로지로 표현할 수 없는 조건 | 트레이스의 `cannot_answer`·`reason` | 질문 안내, 모델러에게 온톨로지 보강 | 10.4 |
| "권한 없음" | 질문에 읽을 수 없는 타입이 나옴 | 트레이스 `forbidden` | 권한 부여 또는 안내 | 8.4 |
| "게시된 온톨로지가 없어 조회할 수 없습니다" | 게시본 없음 | 온톨로지 화면 | 모델러가 게시 | 6.4 |
| "조회 시간이 초과되어 실패" | 질문 범위가 너무 넓음, 데이터베이스 느림 | 트레이스 지연 | 조건 좁히기, 계속되면 개발팀 | 10.7 |
| "조건에 맞는 대상이 너무 많습니다" | 결과가 너무 큼 | — | 조건 좁히기 | 10.7 |
| 답이 예전 데이터 | 동기화 실패, worker 멈춤 | 매핑 카드의 마지막 실행, 현황의 worker | 원인 해결 후 지금 동기화 | 12.5, 27.3 |
| 숫자가 틀림 | 질문 해석 차이(조건 누락) | 트레이스의 `filters` | 질문을 구체적으로, 반복되면 개발팀 | 10.3 |
| 어떤 속성이 갑자기 비어 보임 | 원천 표의 열 이름 변경 | 매핑 카드의 "바뀜"이 전체 행 수 | 매핑 재설정 | 12.7 |
| ② 일부 추정·③ 근거 부족이 잦음 | 답 문장이 근거와 맞지 않음 | 트레이스의 지운 인용 | 개발팀에 트레이스 번호 | 10.7 |
| 답이 매우 느림 | 사용자 몰림, GPU 미사용, 첫 질문의 모델 적재 | 트레이스 단계별 지연, 현황의 GPU, `ollama ps` | GPU 확인, 동시 사용 한도 | 29.4, 30.2 |
| 첫 질문만 30초 | AI 모델을 메모리에 올림 | `ollama ps` 의 UNTIL | 정상(잠시 뒤 다시 내려감) | 29.4 |

## 28.7 그래도 모를 때

1. 현황 화면을 캡처합니다.
2. `ontobotctl status` 결과를 저장합니다.
3. 문제 시각 앞뒤의 api·worker 로그를 저장합니다(26.8).
4. 질문 관련이면 트레이스 번호, 배포 관련이면 작업 기록의 로그 파일을 붙입니다.
5. 43장의 장애 보고 양식으로 개발팀에 보냅니다.
