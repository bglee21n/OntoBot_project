# 33장 자주 묻는 질문

## 설치·구성

**Q. Windows Server 2019 에 설치할 수 있나요?**
A. 아니요. WSL2 를 쓰기 때문에 Windows Server 2022(빌드 20348) 이상이 필요합니다. 설치 스크립트가 처음에 확인하고
"Windows Server 2022(빌드 20348) 이상이 필요합니다"로 멈춥니다(5.10).

**Q. GPU 가 없으면 안 되나요?**
A. 설치와 동작은 됩니다. 다만 AI 모델이 CPU 로 돌아 답 하나에 수십 초~수 분이 걸립니다. 현황의 GPU 칸이 "없음(CPU —
느림)"이 됩니다(18.4).

**Q. 서버를 재부팅해도 되나요?**
A. 됩니다. 부팅 예약 작업 `OntoBot-Host` 가 WSL 배포판을 깨우고 포트를 이어 줍니다. 재부팅 5~10분 뒤 현황과 확인 질문을
보세요(5.8). 사용자에게는 미리 알리세요.

**Q. 서버의 IP 나 이름이 바뀌면 무엇을 고치나요?**
A. `app.env` 의 `ONTOBOT_ALLOWED_ORIGINS`·`ONTOBOT_DEPLOYER_URL`(SSO 면 `ONTOBOT_OIDC_REDIRECT_URI` 도)을 새 주소로 바꾸고
반영합니다(30.2). 포트 전달은 부팅 예약 작업이 다시 겁니다.

**Q. 컨테이너가 일곱 개 보이는데 다섯 개라고 들었습니다.**
A. 서비스는 api·worker·postgres·neo4j·ollama 다섯 개, 배포 콘솔(deployer) 하나, 그리고 할 일을 마치면 끝나는 migrate
가 있습니다. migrate 가 `Exited (0)` 인 것은 정상입니다(2.2).

## 계정·권한

**Q. 사용자가 비밀번호를 잊었습니다.**
A. 지금 판에는 비밀번호를 바꾸는 화면이 없습니다. 새 아이디로 계정을 만들어 주거나(7.3), 개발팀에 요청하세요. 처음
비밀번호를 줄 때 사용자가 기억할 수 있는 것을 정하도록 안내하세요.

**Q. 계정을 지울 수 있나요?**
A. 지우는 기능은 없고 **정지**만 있습니다. 감사 기록의 "누가"를 잃지 않기 위해서입니다(7.7).

**Q. 관리자인데 데이터가 안 보입니다.**
A. 역할별 읽기 권한에서 admin 역할에 객체 타입을 골라 주어야 합니다. 관리자도 예외가 아닙니다(8장).

**Q. 정지한 사용자가 "비밀번호가 맞는데 로그인이 안 된다"고 합니다.**
A. 정지된 계정에도 화면은 "아이디 또는 비밀번호가 올바르지 않습니다"라고만 보입니다(7.7). 사용자 목록의 상태를 보세요.

**Q. 감사 로그에서 사용자 id 가 누구인지 어떻게 아나요?**
A. `security.user_created` 기록의 대상 칸 `app_user:N` 의 N 이 그 사람의 id 입니다(9.1).

## 데이터

**Q. OntoBot 이 원천 DB 의 데이터를 바꾸나요?**
A. 아니요. 동기화는 읽기만 하고, Action 도 OntoBot 안의 편집 레이어에만 씁니다. 원천 DB 계정은 읽기 전용으로 받으세요(11.1).

**Q. 동기화가 실패했는데 데이터가 반쯤 들어갔나요?**
A. 아니요. 행 하나라도 실패하면 그 실행 전체가 아무것도 바꾸지 않고 실패합니다(12.5). 데이터는 마지막 성공 때 그대로입니다.

**Q. 원천 표의 열 이름을 바꿨더니 값이 비었습니다.**
A. 지금 판은 동기화 때 열이 있는지 검사하지 않아, 그 속성이 비게 됩니다(12.7). 매핑을 새 열 이름으로 다시 맞추세요.
원천 담당자에게 구조 변경 전에 알려 달라고 요청하세요.

**Q. Neo4j 데이터를 백업해야 하나요?**
A. 아니요. PostgreSQL 에서 언제든 다시 만들 수 있습니다(재구축 — 13.5).

## Action·알림

**Q. 메일·SMS 설정 없이 Action 을 쓸 수 있나요?**
A. 앱 안 알림(알림함)만 쓰는 Action 은 설정 없이 됩니다. 메일·SMS 로 알리는 Action 은 채널을 설정해야 미리보기가 막히지
않습니다(15.3).

**Q. 메일이 안 갔는데 Action 은 실행됐다고 나옵니다.**
A. 맞습니다. 발송 실패와 실행은 별개입니다. 데이터는 바뀌었고 알림만 실패한 것입니다(15.8). 원인을 고치고 필요하면 직접
연락하세요.

**Q. 보낸 메일을 취소할 수 있나요?**
A. 보낸 메일·문자 자체는 되돌릴 수 없습니다. Action 을 롤백하면 받은 사람에게 정정 문구를 보냅니다(15.9).

## 배포

**Q. 업그레이드하는 동안 사용자는 어떻게 되나요?**
A. 앱 중지부터 준비 확인까지(보통 수십 초~몇 분) 접속이 끊깁니다(21.3). 미리 공지하세요.

**Q. 업그레이드 전에 백업을 따로 해야 하나요?**
A. 업그레이드가 시작할 때 자동으로 백업합니다. 그래도 직전에 **지금 백업** 을 하나 더 해 두면 안심입니다(21.1).

**Q. 롤백을 두 번 할 수 있나요?**
A. 아니요. 바로 전 버전 하나만 기억하고, 롤백하면 그 기억을 지웁니다(22장).

**Q. "DB 까지 복원"을 하면 무엇이 사라지나요?**
A. 업그레이드 직전 백업 뒤의 모든 기록 — 대화, Action, 감사 로그, 계정·권한·설정 변경입니다(22.5).

**Q. 배포 콘솔이 안 열리면 업그레이드를 못 하나요?**
A. 명령(`ontobotctl`)으로 같은 일을 할 수 있습니다(21.7, 22.7, 29.2).

**Q. 배포 콘솔에 누가 로그인했는지 알 수 있나요?**
A. 지금 판은 배포 콘솔 로그인을 감사 로그에 남기지 않습니다(9.2). 작업 기록의 "실행" 칸과 감사 로그의 `deploy.*` 로
누가 무엇을 했는지 확인합니다.

**Q. 현황에 "새 배포 콘솔이 준비되어 있습니다"가 사라지지 않습니다.**
A. 갱신 직후에는 1분쯤 남아 있을 수 있고(23.3), 업그레이드·DB 복원을 하면 다시 나타날 수 있습니다(22.5). 이미 그 버전이면
눌러도 해가 없습니다.

## 운영

**Q. 매일 무엇을 봐야 하나요?**
A. 현황(준비 상태·worker·GPU·디스크·백업), 데이터 소스(그래프·충돌·동기화), Action 전체 기록(발송 실패)입니다(25.1).

**Q. 화면의 시각과 서버 로그의 시각이 9시간 다릅니다.**
A. 서버 로그는 세계 표준시(UTC), 화면은 한국 시각입니다. 고장이 아닙니다(00장).

**Q. 트레이스 번호는 어디서 보나요?**
A. 지금 판의 채팅 화면에는 보이지 않습니다. 서버에서 최근 트레이스 목록을 조회해 찾습니다(10.2).

**Q. 동시에 몇 명까지 쓸 수 있나요?**
A. 데이터베이스 연결 수(기본 30)가 동시 질문의 한도이고, 실제로는 AI 모델이 먼저 병목입니다. 개발 PC(GPU 1장) 측정에서
동시 8명은 응답 95%가 23초 안이었습니다(30.2).
