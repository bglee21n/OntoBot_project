# 3장 운영자가 알아야 할 낱말

이 장은 이 책 전체에 나오는 낱말을 운영자의 눈으로 풀어 둔 것입니다. 처음 읽을 때 한 번 훑어보고, 나중에 모르는
낱말이 나오면 다시 찾아보세요. 짧은 뜻만 모은 용어집은 44장에 있습니다.

## 3.1 데이터에 관한 낱말

### 온톨로지

회사 데이터의 **설계도**입니다. 어떤 종류의 대상(시설, 조직, 지역)이 있고, 각 대상이 어떤 정보(이름, 위험등급,
설치일)를 가지며, 대상끼리 어떻게 이어지는지(시설은 조직이 소유한다, 시설은 지역에 있다)를 적어 둡니다.
OntoBot 은 이 설계도를 보고 질문을 이해합니다.

| 설계도의 부품 | 뜻 | 이 책의 예 |
| --- | --- | --- |
| 객체 타입 | 대상의 종류 | 시설(`Facility`), 조직(`Organization`), 지역(`Region`) |
| 객체 | 그 종류의 실제 한 건 | 강남 변전소 01호(`F-0001`) |
| 속성 | 객체가 가진 정보 한 칸 | 위험등급(`risk_grade`), 설치일(`installed_on`) |
| 링크 타입 | 객체 사이 관계의 종류 | 소유 조직(`owned_by`), 소재 지역(`located_in`) |
| Action 타입 | 데이터를 바꾸는 일의 정의 | 위험등급 조정(`adjust_risk_grade`), 긴급 정비 통보(`urgent_notice`) |
| pk | 객체를 하나로 가리키는 값(주민번호 같은 것) | `F-0001` |
| `api_name` | 프로그램이 쓰는 영문 이름. 한 번 정하면 바꾸지 않습니다 | `risk_grade` |

### draft 와 게시(publish)

온톨로지는 **초안(draft)** 에서 고치고, 확정할 때 **게시**합니다. 게시한 버전(게시본)은 고칠 수 없습니다.
고치려면 게시본에서 새 draft 를 만들어 고친 뒤 다시 게시합니다. 게시본은 언제나 하나뿐이고, 새로 게시하면
이전 게시본은 "보관됨"이 됩니다. 운영자가 직접 게시하는 일은 드물지만, 게시본이 없으면 질문도 데이터 연결도
안 되므로 상태를 볼 줄은 알아야 합니다(6장).

### 그래프 투영과 대사

OntoBot 은 객체 사이 관계를 PostgreSQL 과 **Neo4j**(관계를 빠르게 찾는 그래프 저장소) 두 곳에 둡니다.
PostgreSQL 이 원본이고 Neo4j 는 복사본입니다.

| 낱말 | 뜻 |
| --- | --- |
| 투영 | PostgreSQL 의 변경을 Neo4j 에 따라 적는 일. worker 가 계속 합니다 |
| 미반영 이벤트 | 아직 Neo4j 에 적지 못한 변경의 수. 0 근처가 정상 |
| 반영 지연 | 가장 오래 기다린 변경이 기다린 시간 |
| 대사(對査) | 두 저장소의 내용이 같은지 세어 보고 맞춰 보는 일. 하루 한 번 자동, 화면에서 **지금 대사** |
| 재구축 | Neo4j 를 비우고 PostgreSQL 에서 처음부터 다시 만드는 일 |
| stub 노드 | 링크가 가리키는데 객체가 아직 없는 자리표 노드(원천 데이터 문제) |

### 편집 레이어와 편집 충돌

| 낱말 | 뜻 |
| --- | --- |
| 편집 레이어 | Action 으로 바꾼 값을 원천 데이터와 따로 보관하는 곳. 화면에는 편집 값이 보입니다 |
| 값 계보(값 출처) | 그 값이 어느 원천·동기화 실행 또는 어느 Action 에서 왔는지 |
| 편집 충돌 | Action 으로 바꾼 뒤 원천 값도 바뀐 경우. 사람이 "편집 유지(확인)" 또는 "편집 해제"를 정합니다 |

## 3.2 질문과 답에 관한 낱말

| 낱말 | 뜻 | 운영자가 볼 때 |
| --- | --- | --- |
| 조회 계획(plan) | AI 가 질문을 바꾼 조회 조건 묶음. AI 는 SQL 을 쓰지 않습니다 | 트레이스의 "계획" |
| 조회 조건 문장 | 계획을 사람 말로 바꾼 문장(답 위의 회색 줄) | 사용자가 "이해가 틀렸다"고 할 때 |
| 근거(인용) | 답 문장이 기댄 데이터 | — |
| 등급 ①②③ | ① 모든 사실 문장이 근거와 맞음 / ② 일부만 맞음(추정 표시) / ③ 맞지 않음(본문 숨김) | ③이 잦으면 조사 |
| 상태 ok / empty / failed / not_query | 조회 성공 / 결과 없음 / 조회 실패 / 데이터 질문이 아님 | failed 는 장애 신호일 수 있음 |
| 실패 이유 | `plan_invalid`(질문 해석 실패), `forbidden`(권한 없음), `graph_unavailable`(관계 저장소 연결 불가), `llm_unavailable`(답변 모델 연결 불가) 등 | 28장 표 |
| 트레이스 | 질문 한 건이 어떻게 처리됐는지의 기록(계획·조회문·단계별 시간·AI 호출) | 10장 |

## 3.4 Action 에 관한 낱말

| 낱말 | 뜻 |
| --- | --- |
| Action | 데이터를 바꾸는 요청(예: 위험등급 조정) |
| 미리보기 | 실행 전에 바뀔 값·사전 조건·알림 대상을 보여 주는 단계. 미리보기를 만들면 곧 "요청"이 됩니다 |
| 승인 대기 / 실행됨 / 거부됨 / 롤백됨 / 실패 | Action 기록의 상태 |
| 승인하고 실행 | 승인자가 누르는 단추. 승인과 실행이 한 번에 일어납니다 |
| 막힘 | 미리보기에서 실행할 수 없는 사유가 있는 상태(예: 발송 채널 미설정) |
| 롤백 | 실행된 Action 을 되돌리는 일. 아직 안 나간 발송은 취소하고, 이미 나간 메일·SMS 에는 정정 문구를 보냅니다 |
| 발송 | 메일·SMS 한 통. 상태는 대기 / 보냄 / 실패 / 취소 |
| 앱 알림 | 화면 안 **알림함**. 설정 없이 늘 됩니다 |

## 3.6 이 책에서 자주 쓰는 표현

| 표현 | 뜻 |
| --- | --- |
| "반영합니다" | 설정을 바꾼 뒤 컨테이너를 다시 만들어 새 설정을 읽게 하는 것 |
| "다시 시작합니다" | 컨테이너를 껐다 켜는 것(`docker compose restart …`) |
| "현황을 봅니다" | 배포 콘솔의 **현황** 탭을 여는 것 |
| "관리 화면" | OntoBot 웹 화면 상단의 **관리** 메뉴(관리자만 보임) |
| "운영 서버" | 실제로 사용자가 쓰는 OntoBot 서버 |
| "시험 서버" | 이 책을 찍은 서버(00장 "촬영 환경") |
