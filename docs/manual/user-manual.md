# OntoBot 사용자 매뉴얼

OntoBot 은 회사 데이터에 대해 **평소 말하듯 물어보면, 실제 데이터를 찾아보고 근거와 함께 답하는 챗봇**입니다.
"위험등급 3 이상인 시설이 몇 개야?"라고 물으면 데이터를 세어 답하고, 답의 숫자와 이름마다 어디서 왔는지
눌러서 확인할 수 있습니다. 데이터를 바꾸는 요청("이 시설 위험등급을 3으로 바꿔줘")도 할 수 있는데, 이때는
담당자가 승인해야 실제로 바뀝니다.

이 매뉴얼은 컴퓨터에 익숙하지 않은 분도 따라 할 수 있도록 화면 순서대로 적었습니다.

- **모든 사람**: 1~6장(로그인, 질문하기, 답 읽기, 데이터 바꾸기 요청, 알림)
- **현업 전문가**: 7장(인터뷰 워크숍)
- **모델러**: 8~10장(데이터 설계도, 데이터 연결, Action 만들기)
- **챗봇 빌더**: 11장(평가)
- 막히면: 12장(자주 묻는 질문), 13장(낱말 풀이)

설치·서버 관리는 [시스템 운영자 매뉴얼](operator-manual.md)을 보세요.

## 1. 시작하기: 접속과 로그인

1. 크롬이나 엣지 같은 인터넷 브라우저를 엽니다.
2. 주소창에 관리자에게 받은 주소(예: `http://ontobot.corp.local:8000`)를 입력합니다.
3. 로그인 화면이 나옵니다.
   - **아이디·비밀번호**를 받았다면 입력하고 **로그인**을 누릅니다.
   - 회사 통합 계정을 쓴다면 **SSO 로 로그인** 단추를 누르고 회사 로그인 화면에서 들어옵니다.
4. 로그인하면 **채팅(질의)** 화면이 처음으로 나옵니다.

알아 두기:

- 로그인은 일정 시간(기본 8시간) 동안 유지됩니다. 시간이 지나면 다시 로그인하라고 나옵니다.
- 다 쓴 뒤에는 오른쪽 위 **로그아웃**을 누르세요. 공용 PC 에서는 꼭 로그아웃하세요.
- 비밀번호를 잊었거나 계정이 잠겼다면 관리자에게 문의하세요. 비밀번호는 화면에서 직접 바꿀 수 없습니다.

## 2. 화면 둘러보기

맨 위 막대(메뉴)는 내 역할에 따라 보이는 항목이 다릅니다. 오른쪽에는 내 이름과 역할이 보입니다.

| 메뉴 | 무엇을 하나 | 누가 쓰나 |
| --- | --- | --- |
| **채팅** | 데이터에 대해 질문하고, 데이터 바꾸기를 요청 | 모두 |
| **인터뷰** | 업무를 인터뷰로 설명해 데이터 설계도 초안 만들기 | 현업 전문가, 모델러 |
| **온톨로지** | 데이터 설계도 보기·고치기·게시 | 모델러(관리자는 보기만) |
| **평가** | 챗봇이 맞게 답하는지 시험 | 챗봇 빌더, 모델러 |
| **데이터 소스** | 사내 DB 연결, 데이터 가져오기, 편집 충돌 처리 | 모델러(관리자는 보기·일부 처리) |
| **Action** | 데이터 바꾸기 요청·승인·되돌리기, 알림함. 읽지 않은 알림이 있으면 **빨간 숫자** | 모두 |
| **관리** | 사용자·권한·기록 관리 | 관리자 |

> 메뉴가 보이는데 눌렀을 때 "이 화면을 볼 권한이 없습니다"가 나오면 내 역할로는 쓸 수 없는 화면입니다.

## 3. 질문하기

### 3.1 기본 사용법

1. 화면 아래 입력 칸에 질문을 씁니다.
2. **Enter** 를 누르거나 **보내기**를 누릅니다(줄을 바꾸려면 **Shift + Enter**).
3. 답이 나올 때까지 진행 상황이 차례로 보입니다.
   - "질문을 조회 조건으로 바꾸는 중…" → "조회하는 중…" → "답을 쓰는 중…" → "근거를 대조하는 중…"
4. 보통 몇 초, 사람이 많을 때는 수십 초 걸릴 수 있습니다. 기다리는 동안 다른 질문은 보낼 수 없습니다.

### 3.2 이런 질문을 할 수 있습니다

아래는 샘플 데이터(시설·조직·지역) 기준 예시입니다. 우리 회사에 등록된 데이터 종류로 바꿔 물으면 됩니다.

| 종류 | 예시 |
| --- | --- |
| 개수 세기 | 위험등급이 3 이상인 시설은 몇 개야? |
| 목록 보기 | 변전소 목록 보여줘 |
| 순위·상위 몇 개 | 위험등급이 가장 높은 시설 5개 알려줘 |
| 묶어서 세기 | 시설 유형별 개수 알려줘 |
| 한 대상의 정보 | F-0007 시설의 설비 용량은? |
| 날짜 조건 | 2015년 이전에 설치된 철탑은? |
| 평균·합계 | 용량이 1000kW 넘는 변전소의 평균 위험등급은? |
| 관계 따라가기 | 강남지사가 소유한 시설 목록 보여줘 / 서울에 있는 변전소는? |

### 3.3 이어서 묻기

바로 앞 답에 나온 대상들을 가리켜 이어서 물을 수 있습니다.

- (시설 목록이 나온 뒤) "**그 중** 위험등급이 4 이상인 것만"
- (시설 두 개가 나온 뒤) "**그 시설들의** 설비 용량 합계는?"

이어서 묻기는 **바로 앞의 "목록" 답**을 기준으로 합니다. 개수·평균 같은 숫자 답이나 결과가 0건인 답 뒤에는
"그 중"이 가리킬 목록이 없으므로 처음부터 다시 물어보세요.

### 3.4 잘 묻는 요령

- **대상과 조건을 분명히** 말하세요. "시설 알려줘"보다 "위험등급 4 이상인 변전소 목록"이 정확합니다.
- 숫자·날짜·이름은 **정확히** 적으세요. 이름은 등록된 이름과 글자 그대로 같아야 찾습니다
  (예: "강남 변전소 01호"를 "강남변전소1호"라고 쓰면 못 찾을 수 있습니다).
- 한 번에 하나씩 물으세요. 여러 질문을 섞으면 해석이 틀릴 수 있습니다.
- 등록되지 않은 정보(예: 점검원 이름이 데이터에 없음)는 답할 수 없습니다. 이때 챗봇은 지어내지 않고
  "질문을 조회 조건으로 바꾸지 못했습니다"라고 알립니다.

### 3.5 대화 목록

- 왼쪽에 지난 대화가 최근 순으로 보입니다. 누르면 그 대화를 다시 볼 수 있습니다.
- 새 주제로 묻고 싶으면 **새 대화**를 누르세요(이전 대화의 "그 중" 맥락이 섞이지 않습니다).
- 내 대화는 나만 볼 수 있습니다. 오래된 대화는 회사 보관 기간이 지나면 자동으로 지워집니다.

## 4. 답 읽는 법: 근거와 등급

답은 다음 순서로 보입니다.

```
┌───────────────────────────────────────────────┐
│ 조회 조건: 시설 · 위험등급 ≥ 3 · 건수           │  ← 챗봇이 질문을 이렇게 이해했다
│                                               │
│ 위험등급이 3 이상인 시설은 18개입니다.          │  ← 답 본문
│                                               │
│ [① 근거 확인]  [근거 칩] [근거 칩] …            │  ← 등급과 근거
└───────────────────────────────────────────────┘
```

### 4.1 조회 조건 — 먼저 확인하세요

**조회 조건**은 챗봇이 내 질문을 어떻게 이해했는지 보여 줍니다. 사람이 아니라 프로그램이 조회한 내용 그대로
만든 문장이라 정확합니다.

- 예: "시설 · 시설 유형 = 변전소 · 소재 지역[지역: 지역명 = 서울] · 최대 20건"
- 내 질문의 조건이 빠져 있거나 다르게 이해했다면, 답이 그럴듯해 보여도 **질문을 고쳐 다시 물어보세요.**
- "관계 정보는 ○○:○○ 기준"이 함께 보이면, 시설–조직 같은 관계 정보가 그 시각 이후로 아직 반영되지 않았다는
  뜻입니다(잠시 뒤 다시 물으면 최신이 됩니다).

### 4.2 등급 — 답을 얼마나 믿어도 되나

| 표시 | 뜻 | 어떻게 받아들이면 되나 |
| --- | --- | --- |
| **① 근거 확인** | 답의 사실 문장이 모두 데이터와 글자 그대로 맞음 | 믿고 써도 됩니다 |
| **② 일부 추정** | 근거를 찾지 못한 문장이 있어 그 문장 앞에 **추정** 표시 | 추정 표시된 문장은 근거 카드로 직접 확인하세요 |
| **③ 근거 부족** | 근거와 맞는 답을 만들지 못함 | 본문 대신 안내 문구만 나옵니다. 근거 목록을 직접 보거나 질문을 바꿔 보세요 |

등급은 AI 가 스스로 매기는 것이 아니라, 서버가 답의 숫자·이름을 실제 데이터와 하나하나 대조해서 정합니다.

### 4.3 근거 칩과 근거 카드

답 아래의 작은 단추(**근거 칩**)는 답이 기댄 데이터입니다. 누르면 오른쪽에 **근거 카드**가 열립니다.

- 그 대상의 **지금** 값들이 보이고, 답에 인용된 칸은 **굵게** 표시됩니다.
- **마지막 동기화**: 그 값을 원래 시스템에서 언제 가져왔는지.
- **값 출처**: 어느 시스템·어느 동기화에서 왔는지.
- **편집됨** 표시가 있으면 원래 시스템 값이 아니라 Action(5장)으로 바꾼 값이라는 뜻입니다. "원천 값 ○○"으로
  원래 값과 누가 언제 바꿨는지 함께 보입니다.
  - "원천이 바뀜: …"이 빨갛게 보이면, 바꾼 뒤에 원래 시스템 값도 바뀌었다는 뜻입니다. 화면에는 계속 바꾼
    값이 보이며, 담당 모델러가 어느 쪽을 쓸지 정합니다.
- 개수·평균 같은 숫자 답의 근거는 "집계 결과"라 카드가 따로 없습니다. 조회 조건이 곧 근거입니다.

### 4.4 이런 답이 나오면

| 화면 | 뜻 | 할 일 |
| --- | --- | --- |
| **결과 0건** — "조회 조건(…)에 맞는 객체가 없습니다" | 조회는 성공했고, 조건에 맞는 데이터가 정말 없음 | 조회 조건이 내 뜻과 맞는지 확인 |
| **조회 실패 · 질문 해석 실패** | 질문을 조회 조건으로 바꾸지 못함(데이터에 없는 정보를 물었거나 표현이 모호) | 대상과 조건을 더 구체적으로 다시 질문 |
| **조회 실패 · 권한 없음** | 내 역할로 볼 수 없는 데이터 | 필요하면 관리자에게 권한 요청 |
| **조회 실패 · 시간 초과 / 실행 오류** | 일시적인 시스템 문제 | 잠시 뒤 다시 시도. 계속되면 운영자에게 알림 |
| **조회 실패 · 관계 저장소 연결 불가** | 관계(○○지사 소유 등) 정보를 쓸 수 없음 | 잠시 뒤 다시 시도. 관계가 필요 없는 질문은 정상 |
| **조회 실패 · 결과 과다** | 조건에 맞는 대상이 너무 많음 | 조건을 좁혀서 질문 |
| **조회 실패 · 답변 모델 연결 불가** | AI 모델이 응답하지 않음 | 잠시 뒤 다시 시도. 계속되면 운영자에게 알림 |
| "저는 등록된 데이터를 조회해 답합니다…" | 인사·잡담처럼 데이터 질문이 아니라고 판단 | 데이터에 대한 질문으로 다시 |

> **"조회 실패"와 "결과 0건"은 다릅니다.** 실패는 "알 수 없다"는 뜻이지 "없다"는 뜻이 아닙니다. 실패 답을
> "없다"로 받아들이지 마세요.

## 5. 데이터 바꾸기 요청 (Action)

**Action** 은 데이터를 바꾸는 미리 정해진 일입니다(예: "위험등급 조정", "점검 요청"). 어떤 Action 이 있는지는
회사마다 다르며, 모델러가 정합니다. 모든 Action 은 다음 순서를 밟습니다.

```
요청(미리보기) → 승인자 승인 = 실행 → (필요하면) 롤백(되돌리기)
       └ 요청자가 거두기 / 승인자가 거부
```

- 실행하면 **원래 시스템의 데이터는 바뀌지 않습니다.** OntoBot 안의 "편집 레이어"에 바뀐 값이 기록되고,
  답과 근거 카드에는 바뀐 값이 "편집됨"과 함께 보입니다.
- 실행하면 관련자에게 알림(앱 알림, 설정에 따라 메일·SMS)이 갈 수 있습니다. **메일·SMS 는 보내고 나면 되돌릴
  수 없습니다.** 롤백하면 받은 사람에게 정정 문구가 다시 갑니다.

### 5.1 채팅으로 요청하기

1. 채팅 칸에 바꾸고 싶은 내용을 그대로 씁니다.
   - 예: `F-0004 시설의 위험등급을 3으로 바꿔줘`
   - 예: `부산 철탑 02호 긴급 점검 요청해줘`
   - 예: (시설 목록을 본 뒤) `그 시설 위험등급을 2로 낮춰줘` — 앞 답에 시설이 하나일 때
2. 챗봇은 **바로 실행하지 않고** "Action 요청" 카드를 보여 줍니다.

**경우 ① 요청이 만들어졌을 때** — "미리보기를 만들었습니다"

카드에 다음이 보입니다. 꼼꼼히 확인하세요.

| 항목 | 내용 |
| --- | --- |
| 대상 | 어느 객체를 바꾸는지(이름과 식별자) |
| 바뀔 값 | 지금 값 → 실행 후 값 |
| 사전 조건 | 실행해도 되는 상태인지(✓ 통과 / ✗ 실패) |
| 알림 | 누구에게 어떤 문구가 가는지. "되돌릴 수 없음"은 메일·SMS |
| 상태 | **승인 대기** → 승인자가 결정하면 **실행됨** / **거부** 등으로 바뀜 |

- 내용이 틀렸으면 **요청 거두기**를 누르세요. 그리고 질문을 고쳐 다시 요청합니다.
- 승인자가 따로 정해진 Action 이면 "승인을 기다립니다"가 보입니다. 승인되면 알림이 옵니다.

**경우 ② 요청을 그대로 만들 수 없을 때** — "요청을 그대로 만들 수 없습니다"

챗봇은 확실하지 않은 대상·값을 **짐작해서 채우지 않습니다.** 대신 **확인할 것**과 함께 요청 양식을 보여 줍니다.

| 확인할 것의 예 | 이유 | 할 일 |
| --- | --- | --- |
| '제주 변전소 99호' 에 해당하는 시설 객체가 없습니다 | 등록된 이름·식별자와 글자 그대로 맞는 대상이 없음 | 정확한 이름이나 식별자(pk)를 입력 |
| 이름이 '○○' 인 시설이 여러 개입니다 | 같은 이름이 둘 이상 | **후보** 중 식별자를 골라 입력 |
| '새 위험등급' 값이 필요합니다 | 질문에 바꿀 값이 없었음 | 값을 입력 |
| 대상 '○○' 이 질문에도 맥락에도 없습니다 | 챗봇이 대상을 짐작하려 함 | 대상을 직접 입력 |

양식에 대상(식별자)과 값을 채우고 **미리보기**를 누르면 경우 ①과 같은 요청이 만들어집니다.

### 5.2 Action 화면에서 요청하기

1. 맨 위 **Action** 메뉴 → **Action 요청** 칸.
2. Action 을 고르고, **대상 객체 pk**(식별자, 예: F-0004)와 값(별표 `*`는 필수)을 입력합니다.
3. **미리보기**를 누릅니다. 결과는 5.1 의 카드와 같습니다.

같은 내용으로 미리보기를 여러 번 눌러도 요청은 한 번만 만들어집니다.

### 5.3 미리보기에서 "실행할 수 없습니다"가 나오면

빨간 **실행할 수 없습니다** 아래 이유가 적혀 있습니다. 이 요청은 승인할 수 없는 상태(**막힘**)로 기록됩니다.

- **사전 조건 실패**: 예를 들어 "위험등급 3 이상인 시설만 점검 요청 가능"인데 대상이 2등급인 경우.
- **발송 채널이 설정되지 않았습니다**: 메일·SMS 를 보내야 하는 Action 인데 회사에서 아직 설정하지 않음 →
  운영자에게 문의.
- **수신자가 상한을 넘습니다**: 한 번에 보낼 수 있는 인원을 넘음.

**주의** 칸은 막지는 않지만 알아 둘 내용입니다(예: 연락처가 없어 알림을 못 받는 사람이 있음, 개발용 가짜
발송이라 실제로 보내지지 않음).

### 5.4 승인자: 승인·거부

1. **Action** 메뉴 → **승인 대기** 탭에 내가 결정할 요청이 보입니다.
2. 줄을 눌러 펼치고 바뀔 값·사전 조건·알림을 확인합니다.
3. **승인하고 실행** — 그 자리에서 실행됩니다. 메일·SMS 가 포함되면 한 번 더 확인 창이 뜹니다.
   - 실행 직전에 서버가 한 번 더 확인합니다. 그사이 대상 값이 바뀌어 사전 조건이 깨졌거나 데이터 설계도가
     바뀌었으면 실행하지 않고 **실패**로 기록됩니다(사유가 보입니다). 요청자가 새로 요청해야 합니다.
4. **거부** — 사유(선택)를 적고 누릅니다. 요청자에게 거부와 사유가 보입니다.

규칙:

- 요청자 본인은 원칙적으로 자기 요청을 승인할 수 없습니다(Action 정의에서 "본인 실행 가능"으로 정한 경우만 예외).
- 승인할 수 있는 사람은 Action 마다 정해진 역할입니다.

### 5.5 되돌리기(롤백)

실행된 요청은 승인 역할을 가진 사람이나 관리자가 되돌릴 수 있습니다.

1. **Action** → **전체 기록**(또는 승인 대기·내 요청) → 실행된 요청을 펼침 → **롤백**.
2. 확인 창에서 진행을 누르면:
   - 바뀐 값이 원래 값으로 돌아갑니다(편집 해제).
   - 아직 안 나간 메일·SMS 는 취소됩니다.
   - 이미 나간 메일·SMS·앱 알림 받은 사람에게는 **정정** 문구가 갑니다.
3. 상태가 **롤백됨**으로 바뀝니다.

### 5.6 기록 보기

**Action** 화면의 탭:

| 탭 | 보이는 것 |
| --- | --- |
| 승인 대기 | 내가 승인할 수 있는 대기 중 요청 |
| 내 요청 | 내가 한 요청 전부 |
| 전체 기록 | 내가 볼 수 있는 모든 요청 |

각 요청에는 상태, 요청자·결정자와 시각, 실패·거부 사유, **발송** 결과(대기·보냄·실패·취소)가 남습니다.
상태 이름: 승인 대기 · 막힘 · 거부 · 실행됨 · 실패 · 롤백됨.

## 6. 알림 확인하기

- 누군가의 Action 이 실행되어 내가 받을 사람이면 **앱 알림**이 옵니다.
- 맨 위 **Action** 메뉴 옆의 **빨간 숫자**가 읽지 않은 알림 수입니다(30초마다 새로 확인).
- **Action** 화면 맨 아래 **알림함**에서 내용을 보고 **모두 읽음**을 누릅니다.
- **정정** 표시가 붙은 알림은 앞서 받은 알림이 롤백되어 무효가 되었다는 뜻입니다.
- 메일·SMS 로도 받으려면 관리자에게 메일 주소·휴대전화 번호 등록을 요청하세요(회사에서 메일·SMS 를 설정한
  경우에만).

## 7. 현업 전문가: 인터뷰 워크숍

데이터 설계도(온톨로지)를 처음 만들거나 넓힐 때, 업무를 가장 잘 아는 분이 **AI 면담자의 질문에 답하는 방식**
으로 업무를 설명합니다. 답에서 "다루는 대상, 확인하는 항목, 관계, 하는 조치, 자주 찾는 질문"의 후보가 뽑히고,
사람이 검토해 확정한 것만 설계도 초안이 됩니다.

### 7.1 인터뷰 시작

1. 맨 위 **인터뷰** 메뉴 → 제목(선택, 예: "변전소 점검 업무")을 쓰고 **새 인터뷰**.
2. 목록에서 **열기**를 누르면 인터뷰 화면이 열립니다. 인터뷰를 만든 사람이 답하는 사람(인터뷰 대상자)입니다.

### 7.2 질문에 답하기

면담자가 다음 여섯 주제를 차례로 묻습니다. 화면 위에 주제별 진행 상황(대기·진행 중·완료·정보 부족)이 보입니다.

1. **역할** — 어떤 일을 맡고 있는지
2. **업무 흐름** — 일이 어떤 순서로 진행되는지, 다루는 대상(시설·장비·요청 등)
3. **의사결정 지점** — 무엇을 보고 판단하는지, 판단 뒤에 하는 조치
4. **사용 데이터** — 대상마다 확인하는 항목(위험등급, 마지막 점검일 등)
5. **예외 상황** — 평소와 다르게 처리하는 경우
6. **찾아보는 질문** — 평소 자주 찾는 질문과 기대하는 답

답을 입력 칸에 쓰고 **보내기**(또는 **Ctrl + Enter**)를 누릅니다.

답하는 요령:

- **구체적인 이름과 예**를 들어 주세요. "설비를 봅니다"보다 "변전소마다 위험등급과 마지막 점검일을 봅니다"가
  좋습니다.
- 답이 부족하면 면담자가 다시 묻습니다. 모르는 것은 모른다고 답해도 됩니다.
- 개인 전화번호·주민번호 같은 개인정보는 자동으로 가려서 저장되지만, 되도록 말하지 마세요.
- 6번 주제에서는 **실제로 묻듯이** 질문을 말하고 기대하는 답도 알려 주세요. 이것이 나중에 챗봇 시험 문항이
  됩니다.

모든 주제가 끝나면 "인터뷰를 마쳤습니다"가 나옵니다.

### 7.3 뽑힌 요소 검토하기

오른쪽 **검토 목록**에 뽑힌 후보가 종류별(객체 타입·속성·관계·조치(Action) 후보·자주 묻는 질문)로 보입니다.
각 후보에는 **근거 발언**(내가 한 말 중 그 후보가 나온 부분)이 붙어 있습니다.

후보마다 하나를 고릅니다.

| 단추 | 뜻 |
| --- | --- |
| **확정** | 맞다 |
| **수정** → 고친 뒤 **수정 확정** | 대체로 맞는데 이름·종류 등을 고쳐야 한다 |
| **거절** | 틀렸거나 필요 없다 |

- "발언에서 이 문장을 찾지 못했습니다"가 보이면 근거가 맞지 않는 후보입니다. 고치거나 거절하세요.
- "자주 묻는 질문"은 데이터로 답할 수 있는 질문이면 **기대 답변**을 적어야 확정됩니다.

### 7.4 제출과 게시

1. 모든 후보를 확정·수정·거절했으면 **검토 마치고 제출**을 누릅니다. 제출한 뒤에는 더 답할 수 없습니다.
2. 모델러가 **온톨로지 초안으로 게시**를 누르면, 확정한 요소가 현재 설계도 위에 더해진 **새 초안(draft)**
   이 만들어지고, 확정한 질문은 평가 문항 초안에 들어갑니다. 실제 반영은 모델러가 초안을 검토해 게시할 때입니다.

## 8. 모델러: 데이터 설계도(온톨로지) 관리

### 8.1 버전의 개념

- 설계도는 **버전**으로 관리합니다. 상태는 **draft**(작성 중) · **게시됨**(지금 쓰는 것, 하나뿐) · **보관됨**(예전 것).
- 게시된 버전은 고칠 수 없습니다. 고치려면 **이 버전으로 새 draft** 를 만들어 고친 뒤 게시합니다.
- 게시하면 이전 게시본은 자동으로 보관되고, 챗봇은 곧바로 새 버전으로 답합니다.

### 8.2 draft 만들고 고치기

1. **온톨로지** 메뉴 → 게시된 버전의 **이 버전으로 새 draft**(또는 처음이면 **빈 draft 만들기**) → **열기**.
2. **객체 타입 추가**: api_name(영문 이름, 예: `Facility`), 표시 이름(예: 시설), pk(식별자 속성), 제목(이름 속성).
3. **속성 추가**: 이름, 자료형(문자·정수·소수·참거짓·날짜·날짜시각·목록(enum)), 빈 값 허용, 인덱스,
   개인정보 종류(이름·전화·메일 등 — 개인정보로 표시하면 로그·AI 전송 시 가려짐).
4. **링크 타입 추가**: 출발 타입 → 도착 타입, 카디널리티(하나/여럿), FK 속성(출발 타입에서 도착 타입의
   식별자를 담은 속성).
5. 파일로 한꺼번에 바꾸려면 **임포트 (YAML/JSON)**. draft 내용을 문서 내용으로 통째로 바꾸며, 검사에 걸리면
   아무것도 바뀌지 않습니다. 반대로 **내보내기**로 파일을 받을 수 있습니다.

주의:

- 타입·속성의 **api_name 은 한 번 정하면 바꾸지 않습니다**(기록과 연결이 끊깁니다). 표시 이름은 바꿔도 됩니다.
- 이름 규칙: 타입은 영문 대문자로 시작(예: `Facility`), 속성은 영문 소문자로 시작(예: `risk_grade`).

### 8.3 게시하기

1. draft 화면의 **게시 전 검사**에 문제가 없으면 "게시 전 검사를 모두 통과했습니다"가 보입니다. 문제가 있으면
   목록을 보고 고칩니다.
2. **버전 비교**로 기준 버전과 무엇이 추가·삭제·변경됐는지 확인합니다.
3. **게시** → 확인.
4. 게시 직후 채팅에서 대표 질문을 한두 개 물어 정상인지 확인하고, 평가(11장)를 돌려 보길 권합니다.

## 9. 모델러: 데이터 연결과 편집 충돌

### 9.1 데이터 소스 연결

**데이터 소스** 메뉴에서 합니다. 접속 비밀번호는 화면에 넣지 않고, 운영자가 서버에 넣어 둔 이름(시크릿 참조)
만 적습니다.

1. **데이터 소스 추가** → 종류(`postgres`), 이름, **시크릿 참조**(운영자에게 받은 값, 예: `env:ONTOBOT_SRC_FAC`).
2. **접속 시험** → "접속 성공" 확인.

### 9.2 매핑과 동기화

1. **매핑 추가** → 데이터 소스, 객체 타입, 원천 표 → **열 불러오기**.
2. 속성마다 **원천 열**을 고릅니다. 필요 없는 속성은 "(매핑 안 함)".
3. **모드**: 전체(매번 전부, 원천에서 없어진 것은 삭제 처리) / 증분(워터마크 열 — 예: 수정 시각 — 이 커진 것만).
4. **링크 만들기**: 이 표의 FK 속성으로 링크(관계)를 만들지.
5. **일정**: `every:15m`, `every:1h` 처럼. 비우면 수동.
6. **지금 동기화** → **최근 실행**에서 성공과 "읽음 / 바뀜 / 삭제" 건수를 확인합니다.

한 행이라도 값이 맞지 않으면(예: 숫자 칸에 글자) **동기화 전체가 실패**합니다. 실패 사유를 보고 원천 데이터나
매핑을 고친 뒤 다시 돌리세요. 일부만 들어가 데이터가 어긋나는 것을 막기 위한 동작입니다.

### 9.3 편집 충돌 처리

Action 으로 값을 바꾼 뒤 원래 시스템 값도 바뀌면 **편집 충돌**이 생깁니다. 데이터 소스 화면의 **편집 충돌**
패널에 보입니다(편집 값 / 편집 당시 원천 값 / 지금 원천 값).

- **확인**: 편집 값을 계속 쓴다(충돌을 확인했다는 표시).
- **편집 해제**: 편집을 버리고 원래 시스템 값으로 돌아간다.

화면에는 처리 전까지 계속 **편집 값**이 보입니다.

## 10. 모델러: Action 만들기

Action 은 온톨로지 draft 의 **Action** 칸에서 정의하고, 설계도와 함께 게시해야 쓸 수 있습니다.

1. draft 화면 → **Action 추가**(인터뷰에서 확정한 조치 후보가 있으면 **워크숍 Action 후보에서 시작**).
2. 채울 항목:

| 항목 | 설명 | 예 |
| --- | --- | --- |
| api_name / 표시 이름 | 영문 이름 / 화면 이름 | `adjust_risk_grade` / 위험등급 조정 |
| 대상 타입 | 바꿀 객체의 종류 | 시설 |
| 요청 역할 | 요청할 수 있는 역할(비우면 대상을 읽을 수 있는 누구나) | |
| 파라미터 | 요청할 때 받을 값(이름·자료형·필수) | 새 위험등급(정수, 필수) |
| 사전 조건 | 실행해도 되는 대상의 상태 | 위험등급 값 있음 |
| 바꿀 속성 | 어떤 속성을 파라미터 값(또는 고정값)으로 바꿀지 | 위험등급 ← 새 위험등급 |
| 알림 | 채널(앱·메일·SMS), 받는 역할 또는 대상의 연락처 속성, 문구 | `{target}({target_pk}) 위험등급을 {risk_grade}로 조정` |
| 승인 역할 / 본인 실행 | 누가 승인하나 / 요청자가 스스로 실행할 수 있나 | 관리자 |
| 정정 문구 | 롤백 때 메일·SMS 수신자에게 보낼 문구(메일·SMS 가 있으면 필수) | |

규칙과 요령:

- **식별자(pk)·제목(이름)·링크(FK) 속성은 바꿀 수 없습니다.** 게시 전 검사가 막습니다.
- 문구에는 `{target}`(대상 이름), `{target_pk}`(대상 식별자), `{action}`(Action 이름), `{파라미터 이름}`만 쓸 수
  있습니다. 문구는 정해진 틀에 값만 끼워 넣으며, AI 가 쓰지 않습니다.
- 파라미터 이름을 알기 쉽게 지으세요. 채팅으로 요청할 때 챗봇이 이 이름과 설명을 보고 값을 채웁니다.
- 메일·SMS 알림을 넣기 전에 운영자에게 발송 설정이 되어 있는지 확인하세요. 안 되어 있으면 요청이 막힙니다.

## 11. 챗봇 빌더: 답의 품질 평가

**평가**는 미리 정답을 아는 질문들(**골든셋**)을 챗봇에게 실제로 물어, 맞게 답하는지 자동으로 채점하는 기능입니다.
설계도를 크게 바꾼 뒤나 정기적으로 돌려 품질을 지킵니다.

### 11.1 골든셋과 문항

1. **평가** 메뉴 → 골든셋을 고르거나 **새 골든셋**.
2. **문항 추가**:

| 칸 | 뜻 |
| --- | --- |
| 질문 | 챗봇에게 할 질문 그대로 |
| 기대 | 기대 결과: 정상 답(ok) · 0건(empty) · 실패(failed) · 질의 아님(not_query) · Action 요청(action_preview) |
| 필수 값 | 답에 꼭 들어 있어야 하는 값(쉼표로 구분, 예: `18`) |
| 답할 수 있음 | 데이터로 답할 수 있는 질문인지. "답할 수 없음" 문항에 ①·②로 답하면 결함 |
| 권한 | 이 역할 권한으로 물어봄(권한 시험) |
| 장애 주입 | 일부러 장애를 흉내 내 "실패를 숨기지 않는지" 시험 |

인터뷰에서 온 문항은 기대 답변만 있으니, 채점하려면 필수 값을 채우세요.

### 11.2 실행과 결과 읽기

1. **평가 실행** — 실제 AI 모델로 문항마다 몇 초씩 걸립니다(서버의 워커가 실행).
2. 실행 기록에서 **게이트 통과 / 게이트 실패**를 봅니다.

| 지표 | 뜻 | 기준 |
| --- | --- | --- |
| 정답률 | 답할 수 있는 문항 중 맞힌 비율 | 90% 이상(잠정) |
| 근거 인용률 | 보여 준 사실 문장 중 근거가 확인된 비율 | 반드시 100% |
| 권한 위반 | 볼 수 없는 데이터가 답에 나온 건수 | 반드시 0 |
| 실패 은폐 | 장애를 정상 답처럼 보인 건수 | 반드시 0 |
| 답 없음에 ①② | 답할 수 없는 질문에 확인된 답처럼 답한 비율 | 반드시 0 |
| Action 파라미터 정확도 | Action 요청 문항에서 대상·값을 맞게 채운 비율 | 90% 이상(잠정) |
| Action 지어내기 | 없는 대상·값으로 요청을 만든 건수 | 반드시 0 |

3. **문항별 결과**에서 틀린 문항의 답·조회 조건·판정 이유를 확인하고, 설계도(이름·설명)를 다듬거나 개발팀에
   알립니다.

## 12. 자주 묻는 질문

**Q. 답이 틀린 것 같아요.**
A. 먼저 **조회 조건**이 내 질문 뜻과 맞는지 보세요. 맞는데도 값이 이상하면 근거 칩을 눌러 근거 카드의 값과
**마지막 동기화** 시각을 확인하세요. 원래 시스템 값과 다르면 동기화가 늦은 것일 수 있습니다. 그래도 이상하면
질문 시각과 함께 관리자에게 알려 주세요(관리자는 처리 기록을 볼 수 있습니다).

**Q. "질문 해석 실패"가 자꾸 나와요.**
A. 대상(무엇을)과 조건(어떤 것)을 분명히, 등록된 이름 그대로 적어 보세요. 데이터에 없는 정보는 답할 수 없습니다.

**Q. 0건이라는데 분명히 있을 것 같아요.**
A. 조회 조건의 이름·숫자가 정확한지 보세요. 이름은 글자 그대로 같아야 합니다. 그리고 내가 볼 수 있는 데이터
종류인지(권한)도 확인하세요.

**Q. 챗봇에게 바꿔 달라고 했는데 바로 안 바뀌어요.**
A. 정상입니다. 데이터를 바꾸는 요청은 미리보기만 만들고, 승인자가 승인해야 실행됩니다. Action 메뉴의 내 요청에서
상태를 보세요.

**Q. 잘못 요청했어요.**
A. 승인 전이면 **요청 거두기**, 이미 실행됐으면 승인자나 관리자에게 **롤백**을 요청하세요. 메일·SMS 는 되돌릴 수
없어 정정 문구가 다시 나갑니다.

**Q. 바꾼 값이 원래 시스템에도 반영되나요?**
A. 아니요. OntoBot 안에서만 바뀐 값이 보입니다(편집 레이어). 원래 시스템은 바뀌지 않습니다.

**Q. 왜 어떤 문장 앞에 "추정"이 붙나요?**
A. 그 문장의 내용을 데이터에서 글자 그대로 확인하지 못했다는 표시입니다. 근거 카드로 직접 확인하세요.

**Q. 내 질문이 다른 사람에게 보이나요?**
A. 대화는 본인만 봅니다. 다만 문제 해결을 위해 관리자가 처리 기록(개인정보는 가려짐)을 볼 수 있고, 그 열람도
기록에 남습니다.

**Q. 개인정보를 물어봐도 되나요?**
A. 권한이 있는 데이터만 답합니다. 개인정보 속성은 기록·AI 처리 과정에서 가려집니다. 업무에 필요한 범위에서만
쓰세요.
